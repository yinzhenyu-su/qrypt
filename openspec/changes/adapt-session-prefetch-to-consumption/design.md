## Goals / Non-Goals

**Goals:**

- 缩短随机/短暂读取趟的未消费尾部，同时允许长连续读取最终达到现有阶段允许的最大流水线。
- 以字节而非 FUSE 请求次数建立确定性规则；调度过程不读取调试投影，不依赖播放器特有信号。
- 复用现有 scope、缓存、Range 执行器和预算，只有 O(1) 新会话控制状态，不维护另一份块缓存。

**Non-Goals:**

- 不预测视频码率、网络带宽或播放器缓冲秒数；不在首版引入 EWMA、全账号自适应、丢弃率反馈控制器。
- 不修改驱动建议、公共 Go 读取接口、五个现有 TOML 覆盖字段、缓存/加密格式、超时和重试。
- 不将 fixed 改成 adaptive，不修改 ReadStream/直读的预取机制，不通过降低校验或立即交付不完整块换速度。

## Decisions

### 1. 在既有会话控制器中调节 adaptive 的有效范围

内部 `ReadPlan` 保留预取模式及阶段给出的窗口/深度上限；会话在每次消费或补充前解析实际预算/范围，传给现有加载执行。`read_policy.effective` 仍代表配置和能力解析后的策略，实际动态值在读事件/预取计划中显示，不把两者混为一谈。

只有已知长度、当前 SessionID/RequestID、非并发提示且阶段为 adaptive 的挂载路径使用新控制状态；显式 interactive 也可使用该预取适配，但窗口内始终单流。显式 bulk、probe、fixed/disabled、无会话、未知长度、ReadStream 自有 scope、ReadRaw/直读保留原路径。模式切换需显式清理信用：fixed→adaptive 从种子开始；adaptive→fixed 采用原固定规则，不能误用缩小后的 adaptive 数值。

选择此处而非驱动侧改默认，因根因是共享消费/调度时序；选择内部模式而非依据字段来源判断，因相同有效策略必须同义。

### 2. 消费信用与扩张规则

内部单位为 cache chunk，消费信用使用字节。定义：

- `Wcap`：本次阶段允许的单预取窗口字节上限。
- `Dcap`：阶段/调度允许的活动预取窗口数上限，继续受全局/对象预算限制。
- `Hcap = Wcap × Dcap`：该阶段允许的最大前方范围，不包含前台自身必需的读范围。
- `H`：会话当前前方预算；`credit`：尚未用于扩张的唯一成功正向交付字节。
- 种子 `Hseed = min(Hcap, Wcap, 1 MiB)`，按现有 512 KiB 块粒度处理；小于一块的 EOF 尾部仍正常读取。种子只准入一个窗口。

每次初始读取趟建立时以 Hseed 开始、credit 为零。成功读取返回后，依据真实返回的 `[offset, offset+len(data))` 更新本趟已交付末端；只增加新覆盖后缀的字节（首次成功计实际返回字节）。重复页无新增后缀则信用为零。失败返回、stale request、前台尚未交付的缓存/网络进展均不计入。访问分类仍由现有序列逻辑完成，不拿“请求已开始”的预测末端当成功消费。

仅在成功消费更新时执行：当 `credit >= H && H < Hcap`，扣除 H，再将 H 增至 `min(2×H, Hcap)`；大调用可按同一扣除规则跨过多个档位。已经使用的信用不再参与下一次扩张，到达上限时丢弃多余信用，避免将来阶段上限升高时突发扩张。消费统计不以单次 pread/FUSE 请求个数为单位；按相同阶段边界输入的等量字节应得到相同信用结果。

阶段上限增大不直接改变 H。上限降低时 `H = min(H,Hcap)` 并清零旧扩张信用，后续在新上限内重新积累；请求数仍实时受准入限制。尚未完成的有效范围允许收尾，不为缩小数字取消有用加载。重新扩大上限只能依靠新的成功消费。

示例：在阶段上限始终为 Wcap=8 MiB、Dcap=4、种子为 1 MiB 的 adaptive 读取中，H 为 1→2→4→8→16→32 MiB；每次需要新增消费 1/2/4/8/16 MiB。真实 Initial 的 Wcap 可能更小，必须用其真实种子/上限，不能把示例常量写成所有驱动默认。

采用消费信用倍增，而非“连续两次请求就铺满”，避免小 FUSE 请求很快触发大范围；首版也不按下载完成来扩张，避免暂停时自主下载到文件尾。

### 3. 把字节范围和请求数分开执行

每次补充得到 `W = min(Wcap,H)` 与 `D = min(Dcap,ceil(H/W))`，实际前方边界为 `min(cursor + H/ChunkSize, fileEnd)`；窗口只允许覆盖该边界内最近的缺口。就绪块、进行中加载、其他相容加载都占边界内区间，不能因跳过前缀而把尾部推出边界。每次准入还要计算所有本会话已拥有的活动加载，包含首窗预热，不能只数新 pending 列表。

保留现有尾部成批补充、游标缺口/EOF 立即补充、完成触发补洞和容量通知。成批阈值基于本次 W/H，不以旧的最大范围为阈值，否则缩小预算会等不到一批。只变更未来请求形状，不取消并重开已有兼容 Range 来迎合新尺寸。

offset-zero 首窗预热也使用种子及会话身份：不得在控制器外先准入一个完整最大窗口，再向控制器报告小预算。前台交付前可按原规则预热一个种子窗口，但不能获得消费信用；首窗加载和控制器必须共同计数。非零 seek 保留现有等待连续访问后才开始预取的门禁。

先扩大单窗口到 Wcap，再增加活动窗口，减小短读取趟的扇出和短 Range 数；达到长连续上限时仍恢复原 Wcap/Dcap 的形状，避免永久降为一流。

### 4. seek、暂停与缩小规则

真实 seek 复用现有 run/scope 退休机制：取消无前台依赖的过时预取，新读取趟重置种子和信用，频繁 seek 因而始终从小范围重建。不跨读取趟继承“大窗口历史”；也不把其他会话的交付当本会话信用。较短尾页重叠保留原读取趟，只计新后缀。

短暂停只让现有范围填满，不按定时器扩张或反复缩放；超过既有 30 秒控制器空闲期限退休，恢复时重建种子，已有已完成缓存照常复用。close/clear/invalidate/concurrent/disabled 继续使用原依赖保护、取消和迟到身份规则。空闲退休、scope 取消与信用更新必须沿用现有锁序，不引入等待取消的锁反转。

首版收缩来自真实 seek 重置、空闲退休和有效上限降低。记录丢弃证据但不据此增加独立历史反馈器；若联合验收不达标，先分析种子/倍增规则，不临时叠加多个启发式。

### 5. 观测与放大口径

在现有 `prefetch_plan` 等适当事件中记录模式、阶段允许 Wcap/Dcap、当前 H、credit、消费末端、实际边界/就绪前缀/活动窗口和 `seed/grow/seek/idle/cap` 原因。对实际状态的采样仍非原子快照，不驱动调度。状态新增字段限于常量数量，不为线上指标保留随文件长度增长的逐块账本。

离线实验保存完整 source Range、窗口 body_bytes/状态、前台交付区间、会话/读取趟和时间；按区间交集/并集核对已交付前缀、未交付尾部、重复尝试和元数据预热。跨会话共用的数据要标为复用，不能重复归责为浪费。取消窗口内的已用字节与未用尾部不能靠 canceled 标签区分；只有轨迹足够时才量化，无法归属的残差标未知，不伪造精确分解。

主指标沿用 **所有窗口完成/取消/重试的执行器 body_bytes / 调用方成功读取字节**，不是网络线缆字节；另报唯一交付区间大小以暴露重读对分母的影响。测量界限包括 FD 关闭、取消排空后的尾流量。进程统计暖身与被测会话流量分开；日志不完整则放大未知。

### 6. 联合验收，不以减少流量替代播放体验

控制 A 冻结为本次规划开始时的完整工作树（含 SFTP 生命周期、超时分类、尾页与慢链路进展等待修复），记录源码清单/补丁、HEAD、Go 和二进制 hash；已有最终二进制 hash `258ca126177d24da134a75329653b152e4dbf0ee81853d1c21d61c7f024f2fff` 只作历史锚点。B 仅增加本 change。所有新测量重新跑 A，不能拿旧 3.149× 与新日期直接作唯一对照。

| 层次 | 负载 | 验收 |
| --- | --- | --- |
| 正确性 | 非均匀数据、细粒度/大粒度消费、慢进展、暂停/seek/错误、并发与预算一 | 字节一致、无重复信用/越界/超预算、无取消重取循环、资源有界 |
| SFTP 定位短测 | 原 8 MiB 连续 + 四个固定近远点各 2 MiB，共 16 MiB，偏移 +137，第二点后暂停 3 秒 | 三轮每轮放大 ≤2.0×，至少两轮相对 A 降低 ≥30%；每轮首 1 MiB seek P95 与连续段速率退化均 ≤10% |
| 正式 seek | SFTP、Quark 加密视频、Koofr；每轮 ≥20 固定点，独立 cold/warm 及同 FD 会话负载分开 | 每轮 P95 退化 ≤10%，错误/重试无新增；放大和请求数不得增加 >10% |
| 长连续 | 同后端 ≥256 MiB 一 FD 连续读取，逐 8 MiB 记录速率，另测 3/35 秒暂停恢复 | 总有用速率及去首尾后的稳态速率每轮退化 ≤10%，不出现新的周期性无请求空洞；总放大不得增加 >10% |

长连续放大接近 1×（参考目标 ≤1.15×）单独报告，不作为跨全部后端的无条件保证；固定边界/内核预读/关闭尾部计入。短测的 2× 是待验证目标，达不到就保留未验收状态，不改口径或扩大有用读取分母来过关。

每种正式负载至少三轮 A/B、B/A、A/B 串行交替，固定文件/偏移/长度/策略/缓存规则。稳态速率取去除首尾各一个 8 MiB span 后的总字节/总耗时，并列出各 span 和低速分布，不能以峰值代替。P50/P95 统一使用 nearest rank，冷/热不混池。CLI isolated/prefetch/concurrent 分开记录；同 FD runner 不在 seek 中清缓存。禁用持久缓存并使用平台可用的 OS 控制，仍明确保留热块、在途合并、元数据、SSH/CDN 和内核 readahead。首个 1 MiB 完成不是网络首字节或播放器首帧。短测四点 nearest-rank P95 只是四点最大值，不替代正式二十点。

长负载先按实测速率设置充足、各臂一致的 runner 上限，不能用默认 600 秒截断高 RTT 后端；完整保留失败和中断。hash 比较需固定偏移/长度；全零云端样本只有跨臂一致性证据，独立正确性由非均匀测试补足。来源峰值/请求数分别报告，configured streams 不等于实际并行；若主张并行后端收益，须额外取得已实证并行受益的后端。当前 SFTP 一/四流未证实并行收益，不能冒充该证据。

波动超过门槛视为不确定，不平均掩盖某轮退化；任何短/长门槛不通过，不能把 adaptive 行为作为完成优化验收。前置 change 的旧版/实施基线/候选完整矩阵继续独立执行，不因本次 A/B 通过自动完成。

## Risks / Trade-offs

- [小种子增加 Range 打开次数或起步空洞] → 先扩单窗口、保留最近缺口立即补充，记录 Range 尺寸直方图与打开/等待时间；联合验收失败时不全局启用。
- [慢链路仍因长窗口被其他会话分流] → 维持共享公平准入、预算一和多会话测试；不能仅凭更低放大声称已达物理最大带宽。
- [FUSE 交付不等于播放器消费] → 明确观测边界，以保守渐进扩张控制；不新增不可靠播放器速率推断。
- [请求开始时已更新序列末端导致虚假信用] → 单独使用成功交付末端，并核验 request/run/scope 身份；失败/迟到不能推进。
- [上限缩小后老尾部仍在途] → 不取消有前台依赖的加载，暂停新准入，记录过渡超界存量；任何新范围都不得越界。

## Migration Plan

1. 以独立工作树/overlay 冻结 A，保留当前所有未提交修复；按本 spec 只改变 adaptive 会话控制并补测试。
2. 更新开发者说明、调优 skill 与脱敏验证摘要，运行确定性/race、严格 OpenSpec 和项目检查；真实计时与完整 CI 分开。
3. 完成短测和正式跨后端联合门槛后，才把行为作为已验收默认；任一后端缺测就明确限制结论。无配置、公共 API 或磁盘迁移。
4. 如不达标，回退本 change 的自适应控制变更及相应诊断，保留前置的生命周期、块交付与目标进展修复；回退不要求用户清除缓存或重新加密文件。
5. 主规格合并顺序：先 `unify-read-policy-execution`，再本 change。旧主规格的“全部旧预取行为不变”与全文件取消条款由前置 change 的明确迁移/会话隔离规则替换；本 delta 仅新增 adaptive 约束。前置设计的 `chunks×depth` 对 adaptive 解释为允许上限，本设计用 H 决定当前范围；fixed 仍按原乘积执行。不得颠倒同步顺序或直接覆写前置任务状态。
