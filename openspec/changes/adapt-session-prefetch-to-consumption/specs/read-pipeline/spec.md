## ADDED Requirements

### Requirement: 自适应会话预取以消费信用扩张

已知长度且具有效会话和请求标识的挂载读，在阶段预取模式为 adaptive 时，系统 MUST 从一个小预取窗口起步，依据当前连续读取趟中成功交付的唯一正向字节逐步扩大前方预取字节边界。起步窗口 MUST 不超过 1 MiB 及阶段窗口上限。一次扩张 MUST 至多翻倍，且扩张前 MUST 消费至少当前前方字节预算的新字节；已用于扩张的信用 MUST NOT 重复使用。后台完成、缓存填充、空闲许可、重复页、失败请求和旧请求迟到完成 MUST NOT 产生信用。该消费口径 MUST 明确为挂载层成功交付，不得声称为播放器已解码或用户已观看。

#### Scenario: 短读取趟小步启动

- **WHEN** 一个有效会话首次读取或 seek 后仅有少量正向交付
- **THEN** 最多从一个不超过 1 MiB 的预取窗口启动，不能仅因出现 Sequential 阶段或有四个空闲许可就铺满最大范围

#### Scenario: 持续消费允许渐进扩张

- **WHEN** 同一读取趟新增唯一成功交付字节达到当前预算
- **THEN** 允许至多翻倍的预算扩张，使用过的信用被扣除，最终仍受阶段上限和 EOF 约束

#### Scenario: 后台填满后暂停

- **WHEN** 调用方停止消费且边界内预取全部完成
- **THEN** 不产生新扩张信用，不向边界之外继续下载，也不因热块驱逐反复下载

#### Scenario: 尾页重复和迟到结果

- **WHEN** 内核重复读取尾页，或者旧请求在新请求之后返回
- **THEN** 同一字节不被重复计入，旧请求不能更新当前读取趟的预算和游标

### Requirement: 自适应字节范围与活动请求分别受限

系统 MUST 分别约束前方预取字节边界、单次预取 Range 尺寸和活动窗口数。已就绪数据与在途范围 MUST 共同占据前方范围，调度 MUST 优先补齐最近缺口，任何新预取 MUST 不越过当前有效边界。驱动/阶段计划和共享全局/对象预算 MUST 继续限制执行，预算为一仍能复用渐进块并通过容量释放通知补充。阶段上限增大 MUST NOT 自动扩大已建立的自适应预算；上限降低 MUST 停止超限的新准入，已有有用加载按依赖保护规则收尾。

#### Scenario: 同一有效范围不重复补充

- **WHEN** 最近前缀已经在缓存中或由进行中的预取覆盖
- **THEN** 仅填边界内未覆盖的缺口，不因跳过前缀将请求尾部向外推远

#### Scenario: 阶段升级不跳过扩张条件

- **WHEN** 初始阶段转为连续阶段且阶段允许更大的预取上限
- **THEN** 当前自适应预算只通过消费信用增长，不立即恢复最大窗口与最大深度

#### Scenario: 小预算并发与补充

- **WHEN** 文件请求预算为一且目标块的预取仍在缓慢推进
- **THEN** 保持目标进展复用，不新增重复 Range，不持部分许可等待；当前请求结束释放容量后能够补充最近缺口

#### Scenario: 上限收缩不引起取消重取循环

- **WHEN** 前台压力或阶段变化降低有效预取上限
- **THEN** 新请求遵守较低上限，不为强制缩小范围而取消仍有前台依赖的加载，已在途尾部单独记账并最终有界结束

### Requirement: 预取扩张状态跟随读取趟生命周期

真实 seek MUST 重置当前读取趟的扩张信用与起步预算；旧读取趟的大预算 MUST NOT 传给新位置。关闭、失效、清缓存、并发或禁用预取 MUST 沿用现有作用域退休规则。空闲控制器退休后恢复 MUST 从小预算重新建立，已完成块仍可正常复用。状态 MUST 有界且按会话隔离，不得用共享诊断投影或另一个会话的消费更新当前会话决策。

#### Scenario: 扩张后远跳

- **WHEN** 持续播放已经扩大预取范围，随后跳转到远处
- **THEN** 新读取趟从小预算启动，无其他前台依赖的旧预取取消；其他会话的有用加载保留

#### Scenario: 长暂停恢复

- **WHEN** 会话空闲超过既有控制器退休期限后恢复读取
- **THEN** 不继承旧扩张信用，从小预算恢复，缓存命中不受影响

#### Scenario: 关闭后迟到完成

- **WHEN** 已关闭会话的旧预取才结束
- **THEN** 不复活控制器或补充任务，许可恰好释放一次

### Requirement: 预取适配保留显式策略与数据契约

本适配 MUST 仅改变有效挂载会话的 adaptive 预取。fixed 的窗口尺寸与深度语义、disabled/probe 的无预取、显式 interactive 的窗口内单流，以及显式 bulk、未知长度、无会话、ReadStream 和直读的既有行为 MUST 保留。前台请求范围、块认证、最终块校验、有限后缀重试、目标无进展接管、原始 idle/total 与主动取消 MUST 不因扩张规则改变。本适配 MUST NOT 新增用户配置或要求驱动实现新公共接口。

#### Scenario: 固定策略保持原计划

- **WHEN** 驱动为阶段提供 fixed 预取尺寸与深度
- **THEN** 继续执行原固定计划，不套用小窗口启动和消费翻倍规则，仍受预算及能力限制

#### Scenario: 旁路和禁用保持原行为

- **WHEN** 读取为 probe、显式禁用预取、未知长度、无有效会话或使用独立顺序流/直读路径
- **THEN** 分别保留原无预取或有界批次行为，不错误进入此会话适配器

#### Scenario: 适配不削弱慢链路保护

- **WHEN** 单流目标块仍有新进展但累计耗时超过三秒
- **THEN** 保持既有目标进展等待，首个完整目标块就绪即交付；原 total 或调用方期限到达仍结束

### Requirement: 预取流量与扩张决策可核对

调试观测 MUST 区分阶段允许上限、当前自适应字节预算、实际边界、活动窗口数、信用变化与重置/扩张原因。测量 MUST 包含取消和重试收到的明文字节，按完整会话计算执行器流量与有用交付之比；最终取消的加载中已消费前缀 MUST NOT 全部标为浪费。区间覆盖推导的未消费字节 MUST 与 body_bytes、重放、块对齐及跨会话复用分别解释，缺失观测 MUST 明确报告未知；不得冒充线缆流量或播放器首帧。

#### Scenario: seek 取消包含有用前缀

- **WHEN** 一个预取已经交付部分块，随后尾部因 seek 被取消
- **THEN** 所有实际收到的字节计入总流量，同时保留已交付前缀的事实，不将整个取消请求算作浪费

#### Scenario: 相同消费量采用不同请求粒度

- **WHEN** 同一正向字节范围由很多小 FUSE 请求或较少大请求完成
- **THEN** 扩张依据相同的唯一交付字节，调试记录可说明信用与预算变化，而非仅以请求次数判定
