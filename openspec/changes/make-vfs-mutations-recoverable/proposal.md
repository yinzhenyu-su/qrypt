# Proposal

## Why

VFS 当前以路径和整条 pending 记录协调写入、改名、删除、重试及直传，缺少统一的内容所有权和持久事务：已复现日志压缩漏记录、旧操作清除新内容、目录迁移上传到错误层级，以及替换失败丢失新旧远端对象。需要把本地期望、已知远端事实与未完成操作分开，修复整条用户文件操作到网盘发布链路，而不是继续在调用方追加补偿分支。

## What Changes

- 引入每挂载的嵌入式事务账本（存储引擎由 Gate 0 选定），事务性记录相关对象身份、父关系及位置修订、上传代、内容引用和远端操作；不持久化完整远端目录树，不迁移通用 task journal 或读缓存。
- 以领域转换代替任意 `SaveUpload` 和按路径清理；重试、取消、删除及上传完成只能修改自己拥有的对象/上传代，过期操作仍须记录实际远端结果。
- 用可恢复的操作预约协调源、目标和子树；单实例内部保证一致，外部修改尽力检测，不承诺跨客户端协调或所有网盘上的原子替换。
- 统一直传、暂存上传和 fallback 的远端发布协议，保留直传不落本地 staging 的行为；破坏性切换前保存候选身份，超时进入对账，失败不删除唯一可恢复副本。
- 区分普通写入、持久检查点与可上传的冻结提交；检查点不触发上传。快照分别给出活跃会话可继续写入的偏移和重开后可靠恢复的偏移，避免客户端回退或高报。
- 内容以“代文件不可变”建模：Flush 在 `fsync` 与哈希后把可变工作文件原子改名为只读代文件，冻结后再写复制新工作文件，从结构上消除冻结复用与旧哈希秒传。
- 明确目录删除语义：含可见或本地待传子项的目录默认拒绝删除；只有调用方显式删除后代后才允许删除目录，删除与在途子项发布通过子树预约协调，不允许删除后重新发布到已消失的父目录。
- View、上传调度和传输进度从已提交事实派生；保留现有 Task 生命周期、终态权威和调用方暂停语义，不让后台远端观测重写它们。对账和缺源通过追加式 phase 与稳定错误码表达，不破坏旧客户端。
- 一并修复链路上的局部契约错误：解析失败不得当作不存在、无扩展名普通文件不得转为目录、加密包装不得向原始后端传明文名称。
- **BREAKING（磁盘格式，不是公开 API）**：在排他所有权下把旧 `pending.jsonl` 与旧暂存导入新账本，并把旧文件移到旧二进制不会解析或清扫的 `legacy/` 备份位置。新布局使用独立的 `localstate/` 内容目录，避免误跑旧版本时其孤儿清扫删除新数据；新存储接受写入后禁止自动回退旧 journal。旧版本不受支持，降级须有独立恢复方案；升级不能恢复旧版已经丢失的记录。
- 交付按 design.md 的 6 个切片 + Gate 0 推进，切片边界即评审/合并边界；21 项审查回归矩阵内置于 design.md，不依赖外部报告。
- 存储引擎采用前必须通过 Gate 0：桌面、现有无 CGO 构建、Android/iOS 绑定、事务/所有权、启动能力探测、体积与性能预算的实证；不通过时停止这一实现路线并更新规划，不暗中退回双后端。

## Capabilities

### New Capabilities

- `vfs-local-state`: 本地修改的事务持久化、身份与内容所有权、删除/重建、恢复、排他存储访问及旧格式迁移。

### Modified Capabilities

- `upload-pipeline`: 明确 Write/检查点/提交的持久性，统一发布与失败对账，防止过期代覆盖并确保现有入口正确。
- `rename-pipeline`: 协调源/目标/子树并发，正确处理后代定位和远端部分成功，保留加密包装的调用方与后端词汇契约。
- `task-api`: 区分活跃会话可继续写入的偏移与重开后可靠恢复的偏移，明确持久确认语义；保留任务状态与公开入口兼容。
- `mobile-upload-task-observer`: 快照提供可信恢复位置及可识别的对账/等待源信息，仍尊重终态和调用方暂停。

## Impact

- 主要涉及 `pkg/vfs/staging.go`、`source_upload.go`、`mutation*.go`、`upload*.go`，以及 `pkg/vfs/{upload,mutation,delete,view,listing}` 的状态与执行协作；存储实现留在 VFS 本地状态模块内部，不向驱动、Task 或 mobile 泄露 SQL 或具体引擎类型。
- `pkg/core/upload_stream_task.go` 及其恢复、直传路径通过现有 Core/VFS seam 关联内容与操作身份；`pkg/task` 保持通用生命周期和 journal 所有权。
- `pkg/mount/adapter_fuse_file.go`、`pkg/crypt/drive_wrapper.go` 做必要 Adapter 契约修复；现有 driver capability、JSON 入口、任务类型和主要字段保持兼容。macOS Finder 的无扩展名目录创建必须用类型/平台证据适配，不能仅删除启发式而引入回归。
- `pkg/vfs/localstate` 作为各 VFS 域共享的基础状态层，而非平级业务域；需要同步更新包边界、`check-arch.sh`、`CONTEXT.md` 词汇表和 ADR，明确 upload/mutation/delete/view 对它的单向依赖。
- 更新离线 journal 维护入口、调试快照 `cache.journal`、`DebugSnapshotSchemaVersion`、`qrypt fs journal` 输出和用户恢复说明；维护命令使用同一排他所有权与状态转换，不绕过账本。与在途 offline changes 仅在共享传输路径上集成，不扩展离线下载功能。
- 新增存储引擎依赖及平台构建验收，具体实现由 Gate 0 选择（纯 Go SQLite 候选，必要时评估纯 Go KV），不引入可互换多后端。验收包含确定性并发、崩溃点重启、路径型/稳定 ID 后端、直传源失效、目录删除、迁移空间、热路径性能和旧备份保留；测试夹具不得依赖本次审查的 `/tmp` 文件或真实网盘账号。`pkg/vfs/localstate` 需要加入覆盖率门禁，不能只依赖 nightly 偶然发现。
