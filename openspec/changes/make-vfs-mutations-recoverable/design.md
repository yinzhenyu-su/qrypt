# Design

## Context

动机与范围见 [proposal.md](proposal.md)。本设计落实 [本地状态](specs/vfs-local-state/spec.md)、[上传](specs/upload-pipeline/spec.md)、[改名](specs/rename-pipeline/spec.md)、[任务](specs/task-api/spec.md) 与 [移动端观测](specs/mobile-upload-task-observer/spec.md) 的契约。

当前实现的有效基础与限制：

- `pkg/vfs/upload/store.go` 已有 journal-first、条件更新及 `txMu`，但 `appendJournal` 在调用方更新内存前压缩；`TryReuseFrozenStaging` 只在内存解除冻结。不能把现有缓存状态直接视为可靠事务模型。
- `pkg/vfs/upload_recovery.go` 已在恢复时拒绝采纳长度变化的冻结暂存、跳过永久失败记录并暴露相应错误；`TryReuseFrozenStaging` 也已拒绝继承 `ReplaceUpload`/`PermanentFail`。
- 上述两处仍是按路径的单点防护：没有对象身份与持久事务，审查项 1（压缩遗漏已保存记录）与 2（冻结复用恢复旧哈希）只被部分覆盖，不能据此认为已修复。
- `pkg/vfs/upload/interfaces.go` 的 Engine Store seam 已有条件提交，但 `SaveUploadExact`、Retry、删除清理等其他入口仍可绕过身份校验；`sameUploadRecord` 比较大量字段并把时间与修订耦合。
- `pkg/vfs/pathlock` 仅按单路径互斥；`mutation_rename.go` 的 pending rename 只锁源路径，目录迁移与子项暂存建立缺少共同协议。
- `pkg/vfs/upload/{engine,replace,commit}.go` 和 `source_upload.go` 各自执行发布，直传缺少与 pending 的协调；前者先提交 View 再条件删除 pending，失败时反向补偿。
- `pkg/vfs/delete/executor.go` 在远端删除后调用按路径清理；`mutation_remove.go` 将任意 pending 当作仅本地对象。
- `pkg/core/upload_stream_task.go` 的 `Written` 同时用于接受进度、下一写入位置和 ResumeOffset。通用 `pkg/task/persistent_store.go` 不为所有进度变化逐次持久化；任务 journal 不能承担字节恢复事实。
- 现有 `upload-pipeline` 对“成功写入即恢复”的描述比调度文档强。本 change 的 delta 明确改为 Write 与持久确认分层；`rename-pipeline` 的完全失败和部分失败也分别明确，不静默保留矛盾要求。
- `go.mod` 尚无嵌入式 SQL/KV 存储依赖。CI 包含 Windows 无 CGO、Linux 发行构建、Darwin 双架构；`scripts/dev/build-android-aar.sh` 使用 gomobile、Android API 21 与全部 ABI。iOS 绑定需要 macOS 工具链验证，不能根据 Android 成功推断可行。

## Goals / Non-Goals

**Goals:**

- 在单挂载内，以少量领域转换封装本地提交、内容所有权、冲突协调与远端结果对账。
- 本地有效视图一致；远端在可执行且无未解决冲突时最终收敛，替换允许正式名称短暂缺失。
- 保住已持久确认内容和不可逆步骤后的可恢复候选；把不确定结果作为独立的恢复事实。
- 复用现有 VFS/Core/driver seam 和上传静默窗口、并发准入，不要求公开调用方理解内部 transport。

**Non-Goals:**

- 不保证跨客户端原子一致、网盘请求恰好执行一次，或没有版本能力时识别所有外部 ABA 修改。
- 不建立完整持久 inode/远端镜像树，不改造所有 FUSE 已打开句柄语义。
- 不将通用 Task 生命周期、task journal、driver session store、读缓存迁至同一个数据库；不扩展 offline 功能。
- 不引入通用事件溯源框架、全挂载网络锁、多个可互换数据库后端，或本轮随机写块级增量日志。

## Delivery Slices

本 change 的完整范围不可作为一个可评审、可回滚的发布单元。实施按下列切片推进，每个切片独立合并、独立测试、独立回滚；Slice 1 建立开发 seam，Slice 2–5 先通过该 seam 运行，Slice 6 才翻转默认实现。切片边界即评审与合并边界。

| 切片 | 内容 | 是否翻转默认实现 |
| --- | --- | --- |
| Gate 0 | 存储引擎 spike：平台、事务、所有权、体积、性能证据 | 否 |
| Slice 1 | `localstate` 核心：schema、短事务、排他所有权、legacy 导入、开发 seam、边界/词汇 | 否 |
| Slice 2 | content：work/代文件、检查点、冻结、回收 | 否（seam 后） |
| Slice 3 | mutation：对象身份、预约、改名/目录移动/删除/rmdir | 否（seam 后） |
| Slice 4 | publish：直传/暂存/fallback 统一、候选、对账 | 否（seam 后） |
| Slice 5 | 投影/调度/Task/Mobile/可观测性 | 否（seam 后） |

## Decisions

### D1. 用嵌入式事务账本封装本地状态，不把存储细节作为跨模块 Interface

每个实际上传状态目录拥有一个账本及一个写入所有者；沿用现有 mount/StorageLayout 隔离规则，不能只凭挂载显示名称选择目录。新布局固定为 `uploadDir/localstate/`（账本文件由 Gate 0 选定）与 `uploadDir/localstate/staging/`；旧 `pending.jsonl` 和旧 `staging/` 在导入完成后、激活前移到 `uploadDir/legacy/`。这样旧二进制不会把新暂存目录当成自己的孤儿清扫，也不会从旧 journal 复活过期上传。采用事务、唯一约束/关系完整性、单调本地修订和有界等待；若选 SQL 引擎，目标为 WAL 与 `synchronous=FULL`；若选 KV 引擎，必须提供等价的提交、快照与崩溃恢复语义。两者都必须由平台验收确认文件系统和驱动行为，不允许以降低同步换取未说明的持久性退化。

`pkg/vfs/localstate` 被明确为本项目中的**基础状态层**，不是与 upload/mutation/delete/view 平级的业务域：业务域可以依赖它，它不得反向依赖任何业务域、VFS facade、Core、Task 或具体驱动；它只依赖 `drive` 和共享值类型。现有 `package-boundaries.md` 的“子包只拥有单一域”需要增加这一层例外，并在 `check-arch.sh` 中加入方向规则；否则实现时会出现事实上的跨域包却没有边界约束。该决定在 Gate 0 通过后、Slice 1 开始前以 ADR 落定（tasks 1.7），并在 `CONTEXT.md` 补充对象、位置修订、检查点、预约、对账、回收等词汇，词表口径见 [Vocabulary Deltas](#vocabulary-deltas)。

文件内容、哈希计算、网络调用在数据库事务外执行。短事务完成身份检查、记录更新和修订推进；内存投影只能在提交后发布，读者使用同一修订的一致快照。账本之外仍需要内容同步协议，见 D3。

替代方案：继续扩展 JSONL 需要自行实现跨记录事务、重放、索引和安全压缩；本 change 选择嵌入式事务引擎（Gate 0 定具体实现），保留旧格式仅用于受控导入，不长期双写。全局 actor 不是必要前提，可用单写入协调加一致读快照实现；不得将网络放入串行提交入口。

**Gate 0（前置条件，未通过不进入实施）**：先选择并验证可保持现有无 CGO 构建的存储引擎及固定版本，再冻结 D2–D8 的细节。现实候选为纯 Go 的 `modernc.org/sqlite`（主流）与 `ncruces/go-sqlite3`（wazero）；若两者均不满足目标，则评估纯 Go 的嵌入式 KV（如 `bbolt`）作为替代，但**只选定一个生产实现**，不引入可互换的多后端。验收必须包含实际运行证据，而非空包编译：

- 平台：Windows `nocgo`、Linux 发行目标、Darwin amd64/arm64、Android API 21 全 ABI（gomobile）、macOS/iOS gomobile 绑定；缺工具链记为阻塞，不以交叉编译冒充运行验证。
- 事务：CRUD、回滚、重开读取、双进程锁、`BEGIN IMMEDIATE` 语义；WAL 依赖 mmap/共享内存，必须实现**启动能力探测**：探测失败时明确拒绝可写打开并给出恢复路径，不静默降级为 `synchronous=NORMAL/OFF`。
- 排他所有权：引擎自身锁不足以表达“一个状态目录一个写入者”。使用独立 OS 锁文件（Unix `flock`、Windows `LockFileEx`），并验证持锁进程被终止后可重新获取。
- 体积与性能预算（写进验收数字）：单 ABI 二进制增幅、全 ABI AAR 增幅；首次打开耗时、每次提交 p50/p99、Flush 端到端 p99。没有数字的“不明显退化”不作为验收。
- 许可证与传递依赖审查。

无法验证的平台明确阻塞；若没有满足目标的候选，停止依赖引入和生产接线，回到规划，不自行改用未经验证的架构。

**本地预检（部分证据，2026-10-22，linux/amd64，隔离项目，不进入仓库依赖）**：`modernc.org/sqlite v1.61.0` 在 Linux 上以 WAL + `synchronous=FULL` 完成建表、事务提交、关闭、重开读取（`journal=wal`、`synchronous=2`）；`CGO_ENABLED=0` 下 Windows amd64/arm64、Darwin amd64/arm64、Linux arm64、Android arm64 交叉编译通过，最小程序二进制约 9–10 MiB。Android 386/amd64/arm 与 iOS 的 `CGO_ENABLED=0` 失败对**空程序**同样成立，属于 Go 工具链约束，不是引擎缺陷；这些目标由 gomobile 的 cgo 工具链验证，不能用上述失败判定引擎不可用。真实设备/模拟器运行、gomobile bind、iOS 真机、AAR 体积与性能仍是未验证项。

### D2. 分离身份、位置、内容和执行事实

账本只持久化未收敛修改、必要祖先和未完成操作，不复制完整远端树。下表是概念记录，不要求逐字段公开 Go 类型：

| 记录 | 所有权与约束 |
| --- | --- |
| 对象 | 本地稳定对象 ID、文件/目录类型、当前生命周期；删除后重建分配新 ID |
| 位置 | 对象的直接父对象、明文名称、位置修订；同一有效父/名称唯一，目录关系不能成环 |
| 上传代 | 对象 ID、内容代 ID、可变/冻结属性、大小及属于该代的哈希；新内容与执行重试不共用身份 |
| 内容来源/检查点 | 本地文件或应用源关联、可靠连续前缀、内容修订及有效性；持久检查点与可上传状态分离 |
| 远端引用 | 对象/上传代的已知远端结果、候选身份、后端原始元数据或重取依据、对应位置修订；远端 ID 不作为本地对象 ID |
| 操作及尝试 | 逻辑工作 ID、受影响对象/位置、步骤、期望修订、尝试代次、请求证据、确定/不确定结果、失败和重试期限 |
| 内容/目标引用 | 当前期望、检查点和未完成操作的持久引用；运行时读引用受内容模块同一回收协议保护 |

用递增修订而非 `UpdatedAt` 判断并发身份；时间仅用于 mtime、静默窗口和重试。路径是位置关系的查询投影，远端 ParentID 是与位置修订关联的定位结果。稳定 ID 后端可保留仍有效的定位；路径型后端在祖先移动后重新解析，不统一改写所有后代 ParentID。

同一位置的逻辑覆盖按本地接受次序确定当前期望，遵守已有 fail/skip/overwrite 策略；direct 的尝试启动不等于调用成功。允许后续本地修改被接受，但旧操作不能在其后重新选择自身为当前代。旧内容在引用解除前保留；直传源不足以提供可靠读取时不伪造可读字节，成功回传前必须完成有效发布/提交，已被取代则通过现有可识别错误语义报告。

替代方案：继续按路径追加更多校验无法区分删后重建和同路径 ABA；持久化全远端树扩大迁移及最终一致处理范围，均不采用。

### D3. 内容模块区分接受、检查点与冻结

保留 `WriteAt` 的偏移写入。单次操作开始时绑定对象和内容写入许可，不能在写入结束时仅按旧路径重新保存。内容操作由对象/上传代局部同步保护，不在账本事务中复制大文件。

持久检查点顺序为：稳定并校验所确认字节，完成必要文件/新建目录项同步，提交检查点元数据，随后才能对调用方给出可靠确认。文件已同步但元数据未提交时保留文件，恢复不高报进度；元数据不得先宣称文件可靠。冻结在此基础上校验完整内容、绑定哈希并建立可上传工作。

**持久边界**：`durable_offset` 只在“文件 `fsync` + 父目录 `fsync`（平台支持时）+ 账本事务提交”全部完成后推进。Windows 无法对目录 `fsync` 时按平台文档降级说明；macOS 上 Go 的 `File.Sync` 是 `fsync` 而非 `F_FULLFSYNC`，因此默认契约只承诺**进程崩溃级**持久性，抗断电需显式 `F_FULLFSYNC` 并作为可选强化。故障注入按该顺序覆盖每个窗口。

FUSE Flush 仍执行持久化、冻结及延迟调度，不改为同步等候网盘完成。顺序移动端输入使用内部的批次检查点，保持公开调用签名；在已有暂停/正常关闭等合适的受控位置建立检查点。为兼容现有客户端，活跃输入项的 `resume_offset` 继续表示本会话下一写入位置，同时追加 `durable_offset` 表示重开后可靠恢复的位置；没有活跃写入时（包括进程恢复后）`resume_offset` MUST 等于 `durable_offset`，不得高报。普通 Write 返回不表示本次已建立检查点，客户端应使用快照中的 `durable_offset` 判断重启后的可用位置。

内容按**代文件不可变**建模，替代页级写时复制：`WriteAt` 只写可变 `work` 文件；检查点提交前先 `fsync(work)`；Flush/commit 在 `fsync` 与哈希校验后把 `work` 原子 `rename` 成只读代文件并绑定到上传代。冻结是物理属性（不可变文件），不是标志位，因此冻结代的内容与哈希在写入后不会再变化，从结构上消除旧哈希秒传与冻结复用这一整类缺陷。冻结后再次写入时，从代文件复制出新的 `work`（每个冻结周期最多一次，不是每次写），或在整文件覆盖时直接新建。顺序大文件只在 Flush 时冻结一次，不产生额外复制；随机写在 Flush 后至多复制一次。回收按代文件引用计数：仍被当前上传代、检查点、活动读取或未完成操作引用的代文件不得删除。

一般随机写不额外引入块级写日志，以 Flush 冻结的代内容为持久提交；缺口、截断或覆盖不能仅靠文件长度生成续传 offset。未 Flush 的可变内容恢复后保持本地，不自动上传。冻结复制成本必须以基准测试验证，顺序追加检查点不得退化为每次追加都复制整个大文件。

非 NotFound 的 Resolve/List 错误原样传播，不能初始化空暂存；从远端建立暂存的复制必须校验读到的内容及失败清理。所有复制失败保留原有效内容，新增无引用文件只能由安全回收协议处理。

替代方案：每个 Write 都 fsync 成本过高且超出已确认契约；原地修改仍被持久声明为冻结的文件会重现旧哈希缺陷；两者均不采用。

### D4. 短事务与跨网络操作预约分工

预约记录引用逻辑对象、源/目标位置及受影响子树；它不是长时间持有的 mutex。只序列化冲突的远端切换/变更，无关子树继续执行。短事务建立意图及冲突关系，网络执行在外部，结果经条件转换提交。运行时 worker claim 可丢弃，未完成的预约意图和不确定步骤必须持久化。

- **删后重建**：旧对象 A 的删除在途时允许 B 本地写入，B 发布等待旧删除结果明确；删除回调只完成 A，不能调用按路径的 `RemoveUploadState`。
- **目标覆盖**：pending rename 同时保护源和目标，正在从旧目标读取的暂存初始化先结束或被合法重试，不能迟到覆盖源内容。
- **目录迁移**：已有暂存的本地写入继续归属子对象；依赖旧远端位置的暂存初始化须结束后才执行冲突移动，新初始化按预约等待。成功后迁移目录父关系并失效相关定位；不更改后代的直接逻辑父关系。
- **部分成功**：远端改名成功、移动和回滚失败时，在一个本地事务中提交实际中间位置、相关引用及继续对账的操作；不能只提交 View。
- **编辑后删除**：pending 与远端存在独立建模，撤销本地期望后仍需完成原远端对象删除；仅本地对象删除不进行远端访问。
- **目录删除**：`visible` 明确定义为“远端列表可见子项 + 本地待传子项 + 本地创建目录”，而不是只看本地账本。含可见子项的目录默认按 `ENOTEMPTY` 拒绝；rmdir 必须在子树预约下先 `List` 确认空（含 Finder 的 `.DS_Store` 等平台噪声文件），只有调用方显式删除后代后才可撤销目录。目录删除作为子树预约，与后代的在途发布和远端删除协调：已开始的子项发布必须先收敛，否则目录删除返回可重试冲突（`EAGAIN`/`EBUSY`），不能在父目录消失后继续向旧父标识发布。外部客户端并发导致的非空同样返回错误，不静默丢弃。

外部客户端不受预约保护。执行破坏性步骤前用提供者已有身份/版本/列表能力尽力验证；证据不足时阻塞受影响位置并报告，不声称可识别所有外部并发。取消请求也不能证明在途远端调用未生效。

替代方案：全挂载锁会让一个慢网盘操作阻塞所有工作；仅用最终 CAS 无法撤回已发出的远端删除；均不够。

### D5. 一套发布协议，多个真实内容来源

保留 `pkg/vfs/upload` 的远端上传执行 seam，将 `source_upload.go` 的另一路替换流程收敛到共享发布。内容源 Adapter 接受本地冻结源和应用可重开源；不为抽象完整性引入虚构第三来源或强制直传落 staging。

```text
Frozen staging source --+
                        +--> Publication --> Driver
App-provided source ----+

Prepared --> Candidate available --> Switching --> Published --> Cleanup
                   |                    |
                   +--------------------+--> Reconciliation
```

执行远端步骤前提交意图，返回后记录候选/结果。候选命名包含逻辑操作唯一标识，不能只按文件名前缀批量清理；远端定位必须通过 driver 返回条目及包装后的原始元数据保持可用。候选名必须按后端和加密包装的实际名称上限截断/哈希，保持唯一且可重新解析，不能把任意长用户文件名直接拼进临时名。候选可靠记录后才允许删除旧对象。无法确定是否上传/改名成功时记录请求证据并对账；没有可用版本或哈希证据时保守停止，而非用一次 List 缺失推断失败。

切换前已被取代的工作可以在证明所有权后撤销。切换已开始则先对账/收敛操作，再发布最新上传代。完成转换分别记录实际远端结果与当前期望：旧结果不能清除新代，也不能因为失去当前代资格就丢弃远端事实。只有仍满足对象、位置和操作所有权的结果才能更新对应已知远端引用。

直传候选已存在时，即使源失效，也可以继续对账和切换。候选尚不可用而源无法打开时，通过现有 Task 错误/动作表达需要源，不假称本地拥有完整字节。Task 被取消或终态后，账本仍保留必要对账工作，但 Core 不因此重写任务项生命周期。

所有准备、快照、上传及结果提交失败统一分类：确定可重试、确定永久失败、结果不确定。可重试记录 next-attempt 并重新产生调度；状态保存失败时停止依赖该提交的远端步骤，暴露存储健康错误。没有记录成功的失败不能被 worker 丢弃。

不承诺原子替换或完整回滚。候选是唯一可恢复副本时，即使调用返回失败也不删除它；必要清理成为操作后续工作。

### D6. View、调度、Task 是各自职责内的投影

本地有效视图合并一个一致修订下的远端缓存和本地位置/删除/期望内容；缓存记录依赖修订，过期后重新合并。上传完成先原子记录发布事实与本地选择，再对外发布修订/失效，替代 `commit.go` 的先 View 后条件删除/撤销。保留既有本地目录、mtime、rename shadow 及内核失效语义，不把只读缓存作为执行真相。

调度索引从可执行持久工作重建；提交后通知只是优化，还需有防漏的增量追赶或有界再扫描。不恢复逐文件 timer、内容 channel 或拥塞等待 goroutine，保留既有静默窗口、临时文件规则和准入预算。领取/完成覆盖每种结果，失败后不能只释放 claim 而永久遗忘工作。

Core 保存 Task/item 与对象/操作的关联，`resume_offset` 在活跃会话表示本会话下一写入位置，`durable_offset` 表示重开后可靠位置；恢复后没有活跃写入时两者相等。接受字节用于进度，不是持久证据；可通过兼容的快照细节说明持久范围，不重命名现有主要字段。通用 Task journal 不与账本双事务绑定：先提交内容事实，后更新 Task 投影；启动或事件丢失时通过持久关联重建，保留已存在终态、暂停错误及 action 权威。关联必须先于相关内容确认可靠保存，不能仅放在内存或纯进度事件里。

对账和缺源使用追加式可观察编码：新增 display-only phase `reconciling` 和 `awaiting_source`，并配套稳定 `task.Error.Code`（例如 `reconciliation_required`、`source_required`）；不复用 `retrying`/`uploading` 表示“结果待对账”，也不改变现有 `State` 与 action 语义。旧客户端即使不认识新 phase，也必须能从 `State`、错误码和 action 得到可操作结果；未知 phase 只影响展示，不能导致任务被当成成功或可盲目重试。调试快照保留 `cache.journal` 字段作为兼容/legacy 投影，新增 `cache.local_state`，并将 `DebugSnapshotSchemaVersion` 提升为 3；`fs journal` 的命令名和主要输出字段保持兼容，内部改为操作新账本。

### D7. 回收需要引用和删除协议，不是一次目录差集

当前代、检查点、未完成发布和运行时读取都形成内容保护。回收先在状态模块确认并标记不可再建立普通引用的 retiring 状态，再在局部内容同步下删除文件，最后记录完成。新读取/上传必须取得内容许可并重新验证；检查与 unlink 之间不能出现合法新引用。

重启扫描先恢复操作和引用，再发现未登记文件。内容缺失、旧格式哈希可疑或记录损坏时停止相关工作并保留可疑文件；不得因为没有 pending 或只有一个 List 结果就清理。权限保留现有暂存安全等级，不把源 token、认证信息或原始后端敏感元数据写入日志。

旧格式备份必须放在旧二进制不会读取或清扫的 `legacy/` 下，并保持只读；新内容目录不得复用旧 `staging/`。迁移复制旧内容到新目录，预检可用空间，复制失败时原文件不动。激活后旧备份的删除需要显式维护动作，不能在启动扫描中自动清理。无法自动恢复的记录通过 `fs journal` 的兼容输出列出路径、原因和稳定代码；维护命令提供显式的 `recover` 动作（可先 dry-run），由用户确认后再重新验证哈希/重建可上传状态，`prune` 不得删除这些记录。

### D8. 将审查证据转成仓库内独立验收，不依赖临时重现程序

使用 barrier/通道精确安排交错，使用实际内容文件和可控制的本地 HTTP/driver Adapter。路径型与稳定 ID 两类后端都要验证。进程 kill 重启验证进程崩溃；fsync/写入/提交失败注入验证持久协议，不把 kill 测试夸大为真实断电证明。

下表是本 change 自带的、权威的审查回归矩阵，每行自包含问题、触发条件与验收断言；实施者不得依赖本仓库外部的审查报告。若存在外部报告，必须作为链接补入本节，而不是只引用“本次审查”。

| 审查问题 | 必须留下的回归验收 |
| --- | --- |
| 1. 压缩遗漏刚保存记录 | 旧日志阈值处完整导入；新状态维护后 reopen 保留成功提交和暂存 |

### D9. 统一错误分类与可观察码

状态层与业务域对外使用同一套稳定错误分类，避免每个域各自发明字符串，也避免把存储健康问题降级为普通重试：

| 分类 | 含义 | 映射 |
| --- | --- | --- |
| `ErrStale` | 期望的对象/位置/上传代/尝试已过期 | 放弃该次转换，记录远端事实，不重试破坏性步骤 |
| `ErrConflict` | 预约或本地次序冲突 | 调用方可重试；对应 `EAGAIN`/`EBUSY` |
| `ErrUnresolved` | 远端结果不确定，需对账 | 追加 phase `reconciling` + `reconciliation_required` |
| `ErrSourceRequired` | 缺直传源且无候选 | phase `awaiting_source` + `source_required` |
| `ErrStorageUnhealthy` | 提交/持久化失败，存储不可信 | 停止依赖该提交的远端步骤，暴露健康错误，不静默重试 |

边界：所有权占用错误必须在维护命令与挂载入口一致返回；`ErrStale` 不等于失败，过期操作仍须记录实际远端结果。该分类是 `task.Error.Code`、FUSE errno 与调试快照的共同来源。

## Risks / Trade-offs

- [存储引擎平台支持未经验证] → Gate 0 验证全部目标（含 Android/iOS 绑定、Windows nocgo、启动能力探测、体积与性能数字）；缺工具链记为阻塞，不进入生产切换。
- [文件与数据库非同一事务] → 文件同步先于持久声明，代文件不可变保护字节，故障注入覆盖两者之间每个窗口。
- [冻结时复制代文件增加磁盘 IO 与空间] → 每个冻结周期最多一次复制，顺序大文件只在 Flush 冻结一次；以基准测试确认不退化，保留空间预检。
- [移动端二进制体积] → Gate 0 量化全 ABI AAR 增幅；超预算时以纯 Go KV 等替代候选重新决策。
- [存储引擎选型迟滞阻塞规划] → Gate 0 是有时间盒的前置项，未通过即停止并回到规划，不边写实现边赌驱动。
- [单写入入口或子树预约产生等待] → 短事务、有界错误和可观察阻塞；网络在外，无关路径并发，保留现有 worker/准入限制。
- [最终一致或缺少远端身份能力] → 有界退避对账后保留 unresolved 状态和用户可读原因；安全优先，不保证所有外部修改可被检测。
- [Task 与传输事实异步更新] → 持久对象/操作关联、启动和查询对账；不通过后台传输观测复活终态或调用方暂停。
- [存储引擎/WAL 不适合状态目录所在文件系统] → 平台门槛覆盖受支持本地文件系统；锁/同步不可用时明确拒绝可写打开并说明恢复路径，不静默降低持久性或自动搬数据。
- [旧版本不知道新格式] → 新内容放在独立 `localstate/` 目录，旧 journal/暂存移到 `legacy/`；旧二进制误跑不会清扫或复活新数据。旧版本仍不受支持，文档要求停写备份，不能声称格式标志能自动阻止旧二进制。
- [迁移复制暂存需要双倍空间] → 迁移前预检可用空间，复制失败保持原文件不动；不硬链接可被旧版本改写的字节，旧备份保留到用户显式清理。
- [目录删除与在途发布竞争] → 含可见/待传子项的 rmdir 默认 ENOTEMPTY；子树预约等待或拒绝，禁止父目录消失后继续向旧父标识发布。
- [调试/维护输出破坏旧消费者] → schema v3 追加 `local_state` 并保留 `journal` 兼容投影；`fs journal` 命令名和主要字段不变，未知 phase 只影响展示。

## Migration Plan

1. Gate 0（存储引擎 spike）未通过前不写生产接线：先在隔离验证项目产出平台/事务/所有权/体积/性能证据并提交决策记录，再进入 Slice 1。Gate 0 通过后先合入 ADR（tasks 1.7），再进入 Slice 1；Slice 1 提交 `localstate` 基础层与边界规则。每个切片在生产接线前完成确定性回归及新状态模块的独立事务/恢复测试；运行时同一存储目录只启用一种权威实现，允许开发分支逐步构建，但不长期双写。
2. 取得跨进程所有权后，先检查新格式版本和迁移标志；正常挂载及旧 `journal replay/prune` 等入口统一使用这一检查。排他锁使用 OS 可释放机制，不以永久 lock 文件存在性判断占用。
3. 独立的只读 legacy decoder 解释 dirty、clean、rename、clean_batch 及替换状态；不能调用会先 compact 或 sweep 的 `NewPendingStore` 导入。路径/FID/task 关联建立显式映射。
4. 预检可用空间，将旧暂存复制到 `localstate/staging` 并通过只读 decoder 导入旧 journal；不使用旧 `staging/`，也不直接移动或硬链接旧字节。验证文件大小及内容证据；旧 frozen 同长原地改写无法从旧元数据判定是否 Flush，旧哈希全部重新验证；无法证实提交状态的记录保持本地并要求显式恢复，不擅自秒传/上传。缺失或损坏内容形成恢复报告，不初始化空文件。
5. 将导入结果、schema version、旧日志摘要及迁移完成状态提交到未启用的新数据库。把旧 `pending.jsonl` 和旧 `staging/` 移到 `legacy/` 并保持只读；该位置旧二进制不会解析或清扫。迁移失败时原文件不动；中断点可幂等重新复制/导入，不运行孤儿回收。
6. 同步新建数据库及必要目录项后，写入并同步激活记录；激活前禁止新格式接受用户写入。激活后只从新账本执行。
7. `fs journal` 读取新账本并在兼容输出中列出隔离记录；`recover` 先 dry-run 再显式确认，`prune` 不得删除未恢复记录。旧备份的删除必须是独立、显式确认的维护动作，不能在启动时自动清理。
8. 激活前可以丢弃未启用导入结果、保持原格式文件完整；激活并接受新写入后，不自动回退。需要降级时先停止写入、备份数据库/WAL 与全部引用内容，按独立、人工确认的导出/恢复方案处理；本 change 不新增自动降级命令。旧二进制无法被技术上强制阻止，但新布局保证误跑旧版本不会破坏新内容；升级文档必须明确旧版本不受支持。
9. 更新开发者架构、调度、Task 恢复、调试 schema 与用户排障说明；实现阶段按 CI 当前 Go 版本运行完整本地 CI、覆盖率门禁和目标平台验收。规划阶段不引入依赖、不运行实施或提交。

- 顺序输入内部检查点的批次大小和时间间隔：可以测量调整，但不得改变 Write 与持久确认的区分或对外高报 ResumeOffset/durable_offset。
- 对账退避的具体次数和延迟：不影响保守保留及可观察 unresolved 契约，不能通过达到重试次数就自动删除内容。
- 旧备份的保留期限：默认保留到用户显式清理；若后续提供自动清理，必须先完成一次成功启动、确认无未恢复记录，并在文档中给出可恢复窗口。
