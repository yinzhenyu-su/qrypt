## MODIFIED Requirements

### Requirement: interactive 与 probe 不得 fan-out
`interactive` 意图 MUST 对同一文件、同一窗口保持单流，并使用小窗口（默认 1–2 个块）与有界预取；`probe` 意图 MUST 只发起一次小 Range（1 个块）且不预取。两者 MUST NOT 因文件大小或驱动能力而升级为并行 Range。

#### Scenario: seek 保持单 Range

- **WHEN** 调用方以 `interactive` 意图跳转到新 offset 读取
- **THEN** 该次读只发起一个 Range，并取消本会话已过时且无其他前台依赖的后台预取，保留其他会话读取

#### Scenario: probe 只读目标区间

- **WHEN** 调用方以 `probe` 意图读取元数据或小片段
- **THEN** 系统不预取相邻块，也不发起额外 Range

#### Scenario: probe 不受跨块优化放大

- **WHEN** `probe` 读未对齐且跨越块边界
- **THEN** 系统仍只读取目标区间所在的单个块，不套用普通读的两块边界优化

#### Scenario: 多句柄并发不放大

- **WHEN** 同一文件被多个句柄以 `interactive` 意图并发读取
- **THEN** 每个句柄各自保持单流，系统不得按句柄数再放大并行 Range

### Requirement: 直读路径使用相同的并行策略
`fs copy` / `copy` 任务 / `share fetch` 等绕过 VFS 的 `driver.Read` 直读路径 SHALL 使用与 VFS 读相同的驱动能力、默认并行流数和单文件总并发上限；MUST NOT 写入 VFS 读缓存。驱动未声明并行能力或已内部并行时 MUST 保持单流。取消 MUST 停止在途子 Range 并释放并发名额。同一读取源内的 VFS 与直读 MUST 共享文件总预算；直读 MUST 按有界窗口推进，不按整文件预分配分片结果数组。

#### Scenario: drivecopy 大文件并行

- **WHEN** `fs copy` 或 `copy` 任务读取一个超过并行阈值的大文件，且驱动声明并行 Range 能力
- **THEN** 该直读路径使用有界并行子 Range，并按 offset 拼接

#### Scenario: share fetch 回退直读并行

- **WHEN** `share fetch` 无法使用 provider URL，回退到 `driver.Read`
- **THEN** 该回退路径使用相同的并行策略与单文件上限

#### Scenario: 驱动未声明能力时单流

- **WHEN** 直读路径使用的驱动没有声明并行 Range 能力
- **THEN** 该路径保持单流

#### Scenario: 直读不写 VFS 缓存

- **WHEN** `fs copy` / `copy` 任务 / `share fetch` 通过直读路径读取
- **THEN** 不产生 VFS 读缓存块或索引条目

#### Scenario: 取消停止直读子 Range

- **WHEN** 调用方取消直读路径
- **THEN** 在途子 Range 被停止并释放并发名额

### Requirement: 超时错误传播给所有等待者
同一个前台窗口的最终加载失败或超时 MUST 传播给所有等待该前台窗口的读；等待者 MUST NOT 无限重试或继续等待。后台预取被放弃、取消或超时时，仍有效的前台 MUST 按有界接管规则自行取数，不把别人的取消当成自己的取消。前台读超时 MUST 归类为 `drive.ErrorCategoryTimeout`，并由 FUSE 映射为明确的 I/O 错误。

#### Scenario: 加载者超时后等待者立即返回

- **WHEN** 一个读正在加载窗口，其他读在等待同一窗口，加载因超时失败
- **THEN** 所有等待者立即收到超时错误

#### Scenario: 前台读超时映射为 I/O 错误

- **WHEN** 前台窗口取数超时
- **THEN** FUSE 读返回 I/O 错误，而不是继续阻塞

#### Scenario: 后台取消可接管

- **WHEN** 前台调用方仍有效而其等待的预取被取消
- **THEN** 前台可在自身预算内接管加载，不返回其他请求的取消错误，也不重新加入已放弃加载

## REMOVED Requirements

### Requirement: 现有调用方与配置保持兼容

**Reason**: 用户明确允许策略 Go API、配置与诊断 JSON 破坏性迁移；旧条款要求全部调用方/配置行为保持不变，与新迁移边界冲突。

**Migration**: 仓库消费者迁移到新读取源，旧 mounts.read_profile 改为 mounts.read；诊断消费者读取 read_policy。读取字节、Driver.Read、加密格式与缓存格式由新增的“读取接口迁移与数据兼容”保留。

## ADDED Requirements

### Requirement: 读取接口迁移与数据兼容

系统 MUST 保持读取字节、Driver.Read、加密格式和缓存磁盘格式契约。读取策略 Go API、TOML 与诊断 JSON SHALL 采用新结构并允许破坏性迁移；旧配置 MUST 在启动前被明确拒绝并给出迁移提示，不得静默忽略。全部仓库调用方 MUST 迁移到新读取源接口。

#### Scenario: 迁移后数据行为不变

- **WHEN** 调用方完成新接口迁移后读取相同文件
- **THEN** 返回字节与缓存正确性保持不变，读取调度按新策略执行

#### Scenario: 旧配置明确拒绝

- **WHEN** 配置包含旧 mounts.read_profile 表
- **THEN** 加载在启动挂载前失败，错误明确要求迁移至 mounts.read，而非声称继续加载成功

#### Scenario: 无可选建议的驱动继承安全默认

- **WHEN** 驱动仅实现原有 Read 契约且不声明可选读取建议
- **THEN** 使用完整安全默认，保持单流正确性；已有可选策略实现必须迁移

#### Scenario: ReadRaw 不受影响

- **WHEN** 调用方使用 ReadRaw
- **THEN** 仍直接旁路策略与缓存，不把它声称为受共享预算调度的入口



### Requirement: 读取计划具有完整且一致的执行含义

系统 MUST 在执行每次读取前解析完整的窗口、预取、分片、预算和失败处理策略。配置来源只用于诊断；执行 MUST 不因相同有效值来自默认、驱动还是显式覆盖而不同。阶段变化 MUST 完整保留意图门禁、缓存准入、显式优先级与预取禁用；顺序流同样 MUST 在后续窗口应用阶段策略。

#### Scenario: 显式预取深度不丢失

- **WHEN** FUSE 会话确认顺序读取且策略决定预取深度为一
- **THEN** 后续阶段升级仍最多保持一个预取窗口，不因窗口尺寸继承而恢复多窗口启发式

#### Scenario: 顺序流应用连续阶段

- **WHEN** 顺序流从首次读取进入连续读取
- **THEN** 后续窗口使用连续阶段已解析的前台与预取策略，而非永久使用首次策略

### Requirement: 同一读取源按对象共享完整预算

同一读取源与稳定远端对象身份下的前台、直读、探测、重试和预取 MUST 合计遵守有效文件预算与驱动硬限制；不得按 reader、路径或包装对象重新获得额度。加密包装 MUST 计费一次；不同源可独立分配预算。对象改名 MUST 不增加额度；无法取得可靠身份 MUST 明确失败，不跳过预算。

#### Scenario: 混合路径共享预算一

- **WHEN** 同源同文件预算为一，VFS、直读和能力探测同时请求读取
- **THEN** 底层共享层发起的在途读取合计最多一个，取消和正常结束均释放许可

#### Scenario: 加密不重复拿许可

- **WHEN** 加密读取在预算一的源上调用底层驱动
- **THEN** 外层与底层不重复等待同一许可，读取正常完成且总数不超限

#### Scenario: 关闭读取源

- **WHEN** 读取源关闭
- **THEN** 拒绝新读取，取消后台工作，并有界释放其许可和生命周期资源

### Requirement: 准入不形成部分许可等待

前台请求 MUST 仅在全局与文件额度均满足时占用执行许可，等待时不得占据部分许可。预取 MUST 非阻塞尝试完整准入，失败则跳过。后台请求不得抢占已排队且符合条件的高优先级前台；取消与错误 MUST 恰好释放一次许可。

#### Scenario: 文件预算与全局容量均为一

- **WHEN** 前台与预取竞争同一个文件且两种容量均为一
- **THEN** 不形成循环等待，前台在已有读取结束或被合法取消后完成

#### Scenario: 预算一仍可预取

- **WHEN** 前台已交付且源暂时空闲，文件预算为一
- **THEN** 允许一个有界预取使用空闲额度，后续调用仍受同一预算约束

### Requirement: 分片上限与并行数量独立

固定分片模式 MUST 将有界窗口切成不大于分片字节上限的连续任务；任务数可以多于同时运行数，末片不得吸收超出上限的余量。均分模式 MUST 按实际允许的流数覆盖有界窗口。VFS 与直读的相同有效窗口与策略 MUST 得到相同逻辑形状。块对齐及加密扩张 MUST 单独记账且保持数据校验正确。

#### Scenario: 六个分片由三个 worker 执行

- **WHEN** 有界窗口为 24 MiB，分片上限为 4 MiB，并行数为三
- **THEN** 形成六个连续逻辑分片，每个不超过 4 MiB，最多三个同时执行

#### Scenario: 长文件不扩大执行内存

- **WHEN** 整文件直读的文件长度持续增大而窗口与预算不变
- **THEN** 活跃任务和缓冲内存不随文件总分片数增长

### Requirement: 失败分类在读取路径之间一致

系统 MUST 统一传播主动取消、过时请求、远端空闲停顿、总期限、截断和网络失败。本地限速等待 MUST 不计入远端 idle，但仍受单次取数总期限约束。固定低吞吐或含本地等待的总期限到期 MUST NOT 单独成为惩罚连接证据。所有受调度路径 MUST 使用相同的校验、重试及错误原因规则。

#### Scenario: 限速与真正停顿可区分

- **WHEN** 读取因本地限速等待超过 idle 时长
- **THEN** 不产生远端 idle 错误；如果达到 total，返回总期限且不单凭它惩罚连接

#### Scenario: VFS 与直读报告相同停顿原因

- **WHEN** 同一源的两种路径分别遇到真正远端无进展
- **THEN** 均报告远端停顿，驱动获得可区别于主动取消的原因

### Requirement: 窗口接管保护加载身份与会话

放弃等待后，前台 MUST 不重新加入已放弃或取消的加载。旧加载结束 MUST 不删除取代它的新加载；同会话过时预取仅在无其他前台依赖时可取消，不得随意取消其他会话的有用加载。目标自取仍 MUST 遵守文件预算和已有数据校验。

#### Scenario: 旧加载迟到退出

- **WHEN** 前台取代旧预取后旧预取才完成清理
- **THEN** 新加载登记与等待者不受旧清理影响

#### Scenario: 其他会话的预取仍有用

- **WHEN** 一个会话放弃等待另一个会话拥有的预取
- **THEN** 不仅因放弃等待就取消该预取，新的读取仍按共享预算准入

### Requirement: 预取按完成块交付

已知长度对象的 VFS 预取 MUST 保持有界连续 Range，但以完整明文块作为可交付单位；前台 MUST 只等待目标块就绪，不得因窗口其他块尚未完成而延迟交付。普通 Fetch 仍保留整窗成功后返回的语义。块发布后 MUST 不可变；加密认证、范围与超时校验 MUST 保留。最后一块 MUST 在 EOF、长度和关闭校验成功后发布。未知长度对象 MUST 保留整窗验证。

#### Scenario: 目标块早于窗口尾部完成

- **WHEN** 预取首块已完成而后续块仍阻塞，且多个前台会话读取该首块
- **THEN** 所有前台均可取得正确数据，无须等待窗口结束或重复请求；原预取继续持有许可并受预算约束

#### Scenario: 前缀已交付后尾部失败

- **WHEN** 已交付若干完整块，随后出现截断或可重试 idle
- **THEN** 只从首个未交付块重试，沿用原总期限和有限重试次数，不撤回或重复交付前缀，不发布不完整块

#### Scenario: 尾块验证失败

- **WHEN** Range 超长、关闭失败或加密块认证失败
- **THEN** 未通过验证的块不得进入缓存或成功结果；已完整交付的前缀保留流式读取语义，失败作用于未交付尾部

### Requirement: 按读会话维护有界滑动预取

已知长度、具有效读会话标识的挂载读 MUST 以成功消费位置维护前方预取边界，消费推进和加载完成均可触发边界内的补充。系统 MUST 优先补齐靠近消费游标的缺口，就绪数据和在途区间 MUST 计入范围，不得仅因后台完成而无限推进下载尾部。固定深度、意图门禁和共享预算 MUST 保持有效。许可不足 MUST 通过容量释放通知恢复，不能忙等或持部分许可等待。控制器 MUST 有界保留状态；失败和缓存驱逐不得在暂停时引起无限重试或重新下载。

#### Scenario: 预算一完成后继续补充

- **WHEN** 会话预取深度大于一但请求预算为一，首个预取完成且前方范围尚有缺口
- **THEN** 无须等待下次前台读取即可补充最近缺口，最多一个请求在途，下载不超出消费位置决定的前方边界

#### Scenario: 消费推进只填新增范围

- **WHEN** 前方数据已填满，调用方消费一个块
- **THEN** 预取边界只向前滑动对应消费量，优先复用缓存与在途区间，不因跳过已有前缀而额外扩张；远处尾部可积累成批补充，游标缺口和 EOF 不等批次

#### Scenario: 同会话对齐尾部重读

- **WHEN** 已确认连续读取的有效会话因内核页对齐重读前次末尾，重叠小于一个缓存块且新的结束位置不后退
- **THEN** 保持原连续 run 与预取作用域，不把该尾部重读当作 seek；无新增消费时不推进前方边界，真正回退、向前跳空、整块或更大重叠仍按原 seek 规则处理，无会话调用方保持精确相邻规则

#### Scenario: 其他调用方释放容量

- **WHEN** 预取因全局、对象或预取容量不足未能准入，随后直读或其他会话释放容量
- **THEN** 等待的会话被通知并重新尝试完整非阻塞准入，不需要新的前台读触发

#### Scenario: 旧会话退休

- **WHEN** 会话 seek、关闭、变为并发或禁用预取，或文件失效、清缓存和读取域关闭
- **THEN** 旧控制器停止补充，按现有依赖规则取消过时加载；迟到完成不复活旧窗口，其他有效会话受保护，空闲控制器有界清理

### Requirement: 慢链路目标等待复用已有进展

已知长度的单流渐进预取的目标块仍在收到新明文字节时，前台 MUST 复用其进行中的读取，不得仅因累计等待超过固定接管间隔而丢弃部分进展并重新请求。缓存查询与注册合并 MUST 使用相同目标无进展预算；重放字节及目标块之外的流量 MUST NOT 延长该预算。原 total、调用方取消、块校验与许可上限 MUST 保持有效。

#### Scenario: 目标块持续缓慢到达

- **WHEN** 每块耗时超过接管间隔，但目标块持续收到新字节
- **THEN** 前台收到该块后立即交付，不重取该块且不等待窗口尾部

#### Scenario: 进展停止或仅发生在无关位置

- **WHEN** 目标块在无进展预算内未推进，或仅有远处前缀/重放流量
- **THEN** 前台按既有会话保护和预算规则接管，不无限等待

#### Scenario: 缓慢进展达到总期限

- **WHEN** 目标持续收到字节但原 total 或调用方期限先到
- **THEN** 等待仍结束并保留正确超时或取消身份，不重置总预算

#### Scenario: 未知长度不使用渐进等待

- **WHEN** 对象长度未知，预取沿用整窗校验且不能提前交付首块
- **THEN** 前台仍按原固定接管预算旁路，不因收到暂不可交付的前缀续期
