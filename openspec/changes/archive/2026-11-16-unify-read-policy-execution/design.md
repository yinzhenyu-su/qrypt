## Context

实施基线为 fix-remain-issue 分支的 4574fb7；阶段建议、分片旋钮、文件预算及前几轮修复已包含在该提交中。旧实现将可选指针、继承规则和 PrefetchDepthExplicit 带进执行路径；VFS 与直读分别实现取数。这里记录结构问题，不把历史 review finding 当成当前仍未修复的事实。

用户明确允许 Go API、TOML 和诊断 JSON 破坏性迁移。因此选择统一新接口并迁移所有消费者，不建立兼容 facade。Driver.Read、公开移动端读字节入口与磁盘数据格式不因策略重构而改变。

## Goals / Non-Goals

**Goals:** 解析一次、执行一致、预算有唯一所有者；seek 可交付延迟与顺序吞吐分别优化；所有内置驱动均接入，能力不足者安全单流；可在确定性环境复现调度、截断、取消和超时边界。

**Non-Goals:** 不承诺所有云盘必然提速，不加入自学习调参、重复请求竞速、亚块缓存或未校验数据的渐进发布；不修改底层 Driver.Read 契约、不自动增加网络探测或重试次数，不为每个驱动建立独立执行器。

## Decisions

### 1. 四个边界，单向数据流

```
驱动完整 ReadPolicy + 稀疏 ReadOverride + 驱动 ReadLimits
                    ↓ 一次合并与合法性检查
            ResolvedReadPolicy（读取源生命周期内只读）
                    ↓ 意图 + 会话阶段 + 请求 + 缓存状态
              ReadPlan（本次完整执行决定）
                    ↓ 共享准入与取数
          ReadSource / Executor → Driver.Read
```

上述名称为目标内部结构名称。驱动通过 DefaultReadPolicy 构建完整值，再修改需要的字段；没有接口的驱动使用完整内建默认。驱动返回不完整/非法策略时初始化报错，不把零当成继承。配置的“缺省”只存在于 ReadOverride，解析后不再出现 nil、继承标记或 PrefetchDepthExplicit。诊断来源放独立说明中，执行器不读取来源。

拒绝继续扩展旧平铺结构：它会持续制造 merge、clone、hasFields、normalize 和消费者同步修改。此次可以破坏 Go API，直接迁移已有六类 profile 声明及加密包装。

### 2. 完整 profile 的最小职责

| 组成 | 内容与语义 |
| --- | --- |
| Interactive | Initial、Seek、Sequential 三个 AccessPolicy；每个包含前台窗口选择与独立预取策略 |
| Bulk | 有界逻辑窗口字节数、推荐流数、分片策略 |
| Probe | 目标小范围、单流、无预取；不开放并发或预取旋钮 |
| Concurrency | 推荐文件在途请求数；是可被配置覆盖的运行策略，不是 provider 硬能力 |
| Fetch | 每次有界 Range 的 idle 和 total 时间预算 |

WindowPolicy 只含必要模式：Caller（沿用请求大小与现有跨块规则）、Fixed（固定字节窗口）。PrefetchPolicy 为 Disabled、Fixed、Adaptive；Adaptive 只在计划生成阶段使用既有顺序启发式，得到具体窗口数和大小，不新增探测状态机。Fixed 深度为正数；Disabled 无窗口；非法组合直接拒绝。

没有意图的会话使用交互阶段，确认连续后仅按既有能力规则借用 bulk 并行；显式 interactive 始终单窗口单流。缓存准入与显式优先级独立于阶段；probe 和禁用预取的上下文最后覆盖预取决定。无会话信息的前台保持 Initial，不猜测其他会话。

外部尺寸统一为字节，配置接受 KiB/MiB，内置驱动也以字节表达；512 KiB 块对齐仅由 VFS 适配器负责。Seek 候选为一块，未对齐跨块必要数据可合并，不能把候选参数当成所有云盘实测最优值。解析对齐后不得超过内部安全窗口上限 32 MiB；预取深度最多 4，请求数最多 32。

### 3. 新配置只暴露可解释的必要覆盖

新表为 mounts.read。初版允许 max_in_flight 与 bulk 下 streams、window、part_size、min_parallel_size；不开放 fetch 超时与阶段矩阵，不引入全局配置。streams/window/预算字段省略继承，显式零非法；part_size 省略继承，字符串 auto 为均分；min_parallel_size 省略继承，零为不设额外门槛。

```toml
[mounts.read]
max_in_flight = 4

[mounts.read.bulk]
streams = 3
part_size = "8MiB"
```

bulk.window 为一次逻辑窗口，不是文件大小；part_size 是每个子 Range 的最大逻辑字节数，末片只允许更小。删除 ParallelThreshold 的文件大小门槛，使用 min_parallel_size 对本次有界窗口判断，避免大视频的小 seek 被文件总大小影响。对齐或加密造成的底层范围扩张另行记账，不谎称逻辑分片上限等同于线缆字节上限。

### 4. 分片大小与并发数分离

固定分片模式：将有界窗口连续切成不大于 part_size 的任务，数量可以多于流数；推荐流数只限制同时执行的任务数量。24 MiB 窗口、4 MiB 分片、3 流应形成 6 个任务，最多 3 个在途，不产生 16 MiB 末片。均分模式：按最终允许的流数均分有界窗口，完整覆盖且不重复。

VFS 与直读均先划分有界逻辑窗口，再使用同一分片函数。直读按窗口有界推进，不将整文件当作均分对象；执行内存只取决于窗口、在途数和深度，不能预先按文件分片数创建通道数组。保留默认 8 MiB 直读窗口作为迁移基线；显式 bulk.window 对两条路径一致生效。数据仍按顺序交付，整窗/分片验证边界必须写明并保持截断不进入已成功结果。

### 5. 硬限制与读取源的所有权

ReadLimits 表达驱动硬限制，现有 ParallelReadLimiter 和能力声明迁移到单一限制解析入口。无 parallel_range 或存在 internal_parallel_read 时不叠加共享层 fan-out；推荐单流不等于总预算只能为一。最终流数受意图、请求形状、推荐预算、硬限制及当前 grant 约束。

ReadSource 在挂载/驱动实例装配时创建，持有不可变策略、许可调度和对象身份解析；同源的 VFS、ReadStream、下载、drivecopy、share-fetch fallback 注入同一个 source。预算键为源身份加稳定 provider 对象 ID，不使用虚拟路径或包装对象指针作为唯一身份。重命名不产生新预算；加密包装复用源身份并在最外层计费一次，底层原始读取不重复拿许可。不同独立挂载源默认隔离，不承诺跨进程或同账号不同实例的账号级总限额。

便利直读 API 替换为显式 source 入口，删除通过反射指针寻找预算的注册器。standalone 命令创建 source 并复用至命令结束，不能每个文件 read 创建 source。未知 ID 必须先解析稳定身份；解析失败返回错误，不以空键跳过预算。源关闭阻止新请求、取消预取并等待受控读取退出；重配置创建新源，不在有在途请求时替换许可池。

许可计数单位是共享层发起的一次 Driver.Read 及其 body 生命周期，包含能力探测、前台、预取和重试。驱动内部私有 HTTP 并发仍由驱动自行负责，不能宣称共享层可统计它。探测关闭、body 完成/关闭、打开失败和取消均恰好释放一次。

### 6. 调度统一准入，不持有部分许可等待另一许可

复用 readbudget 的调度所有权，将全局槽位与文件额度作为一次准入条件；前台无法取得完整许可时排队且不占部分许可，预取无法立即取得全部许可则跳过。不依赖多个路径自行遵守通道获取顺序。原有全局容量和高优先级预留由运行时创建时设置，策略字段不能扩大它。

高优先级前台优先于尚未开始的预取；不强制抢占其他会话已经运行的前台。释放任一相关许可唤醒符合条件的等待者。允许预算一：前台完成后利用空闲期预取，后续前台可取消本会话已过时预取；不能因为预算一就永远禁用流水，也不能超过限制换取低延迟。

### 7. ReadPlan 完整、不可变且无配置来源分支

输入含 resolved policy、原始意图、会话阶段、请求范围、缓存状态与实际可用资源信息。输出包含具体前台范围/窗口、预取起点/窗口字节数/数量、候选分片形状、优先级、缓存准入、超时和文件预算标识。实际 grant 单独记录；若资源不足引发形状变化，由共享 planner 生成新计划，不就地复制零散字段。

Adaptive 在每次请求边界求值，旧启发式可以保持行为但不能保留到 executor。阶段重分类一次生成完整新计划；FUSE 顺序升级不改原始意图或缓存准入，单独表示并行资格。ReadStream 每次 refill 同样解析阶段，不能永久绑定 Initial。

### 8. 一个取数实现与可靠窗口接管

在不依赖 VFS 的共享读层集中实现有界 Range 打开、strict-range、body 进度、限速等待标记、idle/total、截断校验、幂等重放与按 offset 汇合。VFS 仅适配缓存/窗口合并，直读仅适配有界顺序输出；不为了消除重复引入驱动实现到共享层的反向依赖。

本地限速等待不计远端 idle；每次 Range 的 total 仍含本地等待，是完整时间上限，报 total 时诊断不能声称一定是坏 CDN。区分 CallerCanceled、Superseded、IdleStall、TotalDeadline、Truncated、NetworkFailure；传给驱动的是明确原因，不通过错误字符串和平均速率猜测。只有确切网络停顿、截断或网络失败允许惩罚连接，混有本地等待的 total 到期本身不构成坏连接证据。已经提交给消费者的数据不回放。

对预取目标块的 3 秒无进展预算保留为内部策略。已知长度的单流渐进预取在目标块内部收到新的明文字节时续期，重放字节与无关前缀/尾部流量不能续期；缓存查询和注册合并共用此规则。未知长度整窗回退不续期；无 body 进展的打开或目标停顿仍按预算接管，原执行器 total 和调用方取消仍限制全部等待；收到部分字节不代表块可交付。放弃等待不等于任意取消其他会话加载：同会话且无其他前台依赖时可注销并取消；其他会话保留有用工作，目标自取仍受相同预算。注销和替换按加载身份比较，旧加载结束不能删除新加载。前台不能重新加入已放弃/已取消对象，也不能收到其他加载的取消作为自己的取消；真正前台加载失败仍向其等待者传播。

### 9. 诊断与验收

新 JSON read_policy 包含源作用域、profile 建议、limits、effective，以及字段来源/钳制原因；单次事件含 plan 的意图/阶段/前后台窗口/实际 grant/重试与取消原因。区分 queue、open、body、local_wait、validate、deliver，不将互相重叠阶段简单相加。CDN TTFB 无真实观测时为空，不能用 driver open 冒充；播放器首帧只能由播放器侧测量。预算的对象身份不携带下载签名或凭据。

确定性测试覆盖所有内置驱动契约类型（无 Range、内部并行、单流建议、并行能力、加密、localfs）；真实实测覆盖 Quark、一个高 RTT 单流云盘、一个并行获益后端。旧版 v0.6.1、实施基线、候选同文件同时间窗交替至少三轮，每轮至少 20 个固定 seek 点，分别记录冷/热 P50/P95、持续有效吞吐、错误、请求和下载放大。候选 seek P95 与持续吞吐相对基线不恶化超过 10%，Quark 同时恢复到旧版此范围；声称提速需重复两轮改善至少 20%。不通过则保留驱动参数，不回滚正确性修复；没有账号必须记未实测，性能任务不得勾完成。正常播放无新增错误或异常重放，下载放大不应相对基线增加超过 10%；噪声超阈值则结论不确定，不发布提速结论。

## Risks / Trade-offs

- 统一预算会暴露先前超额并发形成的虚高吞吐 → 同时报真实有效吞吐和实际并发，硬限制不为性能让步。
- 配置与 API 破坏 → 启动前检测旧表/混合新旧表，明确迁移错误；逐个迁移仓库调用点、生成文档与测试，不静默接受。
- 固定分片严格上限改变请求形状 → 记录旧末片吸收与新任务队列的对照，先验证正确性，再测参数。
- 跨会话保留有用预取可能暂占预算 → 同源硬预算优先，不能保证预算一时任意其他会话 seek 立即开始。
- 共享取数扩大改动面 → 按不变量先行测试，先迁移一个源的双路径，再迁移驱动，不另加层层 facade。

## Migration Plan

1. 依赖前两个 change 的实际实现/修复基线；先归档/同步其 delta，再归档本变更。保留历史文档，不重写旧任务完成状态。
2. 以刻画测试固定数据与资源契约，引入新模型和明确 source 所有权；迁移所有 Go 消费者，一次删除旧入口和指针补丁语义。
3. 迁移调度与共享取数，将旧 VFS/direct 重复实现删除；统一错误分类后接入诊断。
4. 切换 mounts.read 与 read_policy JSON，检测旧配置表（不能依赖 TOML 默认忽略未知字段），更新全部 CLI/control/mobile 消费者与生成器。
5. 跑契约/并发/全 CI 与实测后再发布。回滚可整体退回已验证构建；新旧二进制配置互不兼容，用户从本地备份恢复对应配置，程序不自动覆盖配置。缓存与加密数据无需迁移。

### 与现有规格的冲突决议

- read-profile-config 的旧表、bulk 字段、JSON 与兼容性条款由本变更 MODIFIED 明确替换；stage change 中保留旧 Go 字段/不新增用户字段的设计已被用户新决定取代。
- add-read-part-size 的末片吸收与直读整文件分片规则由本变更的有界窗口和严格分片上限替换，不能同时验收两种形状。
- read-pipeline 的“现有调用方与配置保持兼容”替换为数据契约不变、接口允许破坏；ReadRaw 仍直接旁路，不承诺接受 source 预算，本方案不将它作为受调度路径宣传。
- “超时错误传播给所有等待者”保留真正前台失败传播，明确预取取消/接管例外；interactive seek 的“取消文件全部预取”收敛为当前会话，保护其他会话。
- simplify-read-pipeline 的共享取数/窗口工作不重复创建，重叠任务在实施基线中标为由本变更承接，未通过验证不得勾选。

## 预取增量交付补充

Quark 样片日志显示，512 KiB 明文约 167 ms 已到达，但前台仍因 8 MiB 预取整窗提交等待到 3 s。将网络窗口与交付单位分离：保留单个连续 Range 的吞吐与准入，PendingRead.RunChunks 以完整 512 KiB 块转移所有权；VFS 对每块独立通知，窗口身份、会话与许可仍由原生命周期持有。普通 Fetch/Read 继续整窗验证后交付。

完整前缀采用流式成功语义，不因尾部错误撤回；尾块须完成 EOF、超长和 Close 校验。加密包装先认证再输出明文。截断或 idle 重试仅重取尚未发布的后缀，仍共用原 deadline 与重试上限。不按块拆成多个常规请求，避免每块新增请求往返；未知长度保持整窗缓冲。seek 只复用已发布块或大窗口首块，不为远处目标等待无关前缀。

## 播放会话滑动预取补充

由用户追加授权，将已知长度、带有效 SessionID/RequestID 的挂载读取从单次读后批量发起改为会话作用域的滑动窗口。消费成功推进游标；前方边界为游标加已解析的预取窗口大小乘深度，并受 EOF 限制。完成的窗口释放容量后补充同一边界内的最近缺口，而非在已下载尾端继续扩张。准备好的块、已有缓存和在途区间均占用前方范围，保留按块交付与普通整窗语义。

沿用 ReadScope 的 seek、关闭、失效和会话隔离；过期请求不能重建已释放会话。并发提示、禁用预取和清缓存停止旧补充。没有可用许可时只订阅共享调度器的释放通知，仍非阻塞完整准入；不持部分许可、不轮询。缺少会话标识、未知长度及具有自身关闭作用域的 ReadStream 保留有界批次路径。

控制器不新增数据缓存，范围和进行中的请求数受现有大小、深度、文件预算及全局预算约束。只在当前前方范围记住已完成块，避免共享热块驱逐触发暂停时反复下载；真正前台缓存缺失仍按既有路径读取。失败沿用执行器有限重试，补充不得在没有新消费时自行再试。控制器空闲 30 秒退出，随后消费可重新建立；句柄关闭和 seek 无须等待该空闲期限。有限顺序历史淘汰同时退休对应控制器。驱动默认值和自适应规划算法不在本补充中调整，不据此承诺最大物理带宽。

首次真实对照暴露远端尾部碎片：每前进一小段就立即补足整个边界，会产生较多短 Range。远处尾部因此积累到一个计划窗口才补充；深度一使用半个前方范围，保留重叠空间。游标所在缺口和 EOF 不等待批次，补充仍不超原边界。收集完成任务时清除底层切片中的旧加载引用，避免控制器空闲时额外保留已完成窗口数据。

同 FD 实测进一步暴露页对齐尾部重读：未对齐的连续 1 MiB pread 在每个边界可能重新请求末尾 16 KiB 页，精确 offset==前次 end 会误判 seek 并不断取消有用预取。有效会话允许小于一个缓存块、结束位置不后退的尾部重叠，保持已确认 run；非会话调用方仍精确相邻。整块/更大回退、结束位置后退和向前跳空仍属不连续，stale/并发门禁不变。重复尾页不产生额外消费或扩大前方范围。

共享层必须以本次取数上下文实际过期作为 total 判据。驱动的响应头期限或私有子请求也可能返回可匹配 context.DeadlineExceeded 的网络错误；在读取总期限尚有效时保留网络失败身份，不冒充 ReadTotalDeadline，也不因此增加重试次数。

SFTP 的设置期限只覆盖连接检查、打开与定位，返回的 body 使用调用方上下文，不继承驱动私有 15 秒总寿命。共享读取仍由原 idle/total 控制，直接调用 Driver.Read 者自行提供取消/期限并关闭 body。关闭 body 结束取消观察，不反向取消调用方上下文；单请求取消仅在健康探测确认失联后才关闭共享连接，不因读取慢而直接影响其他 Range。此修复不调整窗口、分片、流数、文件预算或共享超时默认。
