## Context

见 proposal.md - Why（含探针输出与真实二进制 A/B 证据）。设计相关的现状约束：

- 日志器的 writer 只有两个来源：`New` 从路径创建的 lumberjack sink（`pkg/logging/log.go:232-244`，同时记录在 `lj` / `errLj` 字段上），以及 `logFile == ""` 时回退的文件对象 `os.Stderr`（`:245-248`，`lj` / `errLj` 均为 nil）。也就是说"谁打开的"完全可以由现有字段判定，不需要新增状态。
- `os.Stderr` 是 `*os.File`，实现 `io.Closer`，所以"关闭所有可关闭的旧 writer"与"关闭日志器自己的 sink"在类型上不可区分。
- 默认全局日志器 `var L = NewDefault()`（`:564`）走 `logFile == ""` 分支，其 writer 就是 `os.Stderr`；CLI 的第一次 `ReplaceDefault` 面对的正是它（`internal/cli/runtime_config.go:43-47`）。
- `ReplaceDefault` 在 `0d3a994` 之前只有测试调用（生产调用点在 `pkg/core/core.go:743`，属嵌入/移动端路径）；CLI 在 `0d3a994` 改为调用它之后，这段清理才第一次在终端场景执行。
- 既有 requirement 的字面（"MUST 释放被替换的日志器的输出目标"）没有区分自有与借用，是这次缺陷的规范层诱因。

## Goals / Non-Goals

**Goals:**

- 恢复"安装日志器之后进程仍能向终端输出"，且不放弃"替换时释放旧文件句柄"。
- 让所有权成为显式规则，写进代码注释与 spec，而不是靠"writer 恰好不是 os.Stderr"的巧合。
- 用可失败的测试把两侧都钉住：借来的不关、自己的仍关。

**Non-Goals:**

- 不改日志的级别过滤、采样、掩码、事件环或 `/v1/events` 查询面。
- 不改 sink 的选择策略（何时落文件、何时落标准错误），也不新增"同时写终端与文件"的 tee——用户的终端日志在改动前也只来自 CLI 的显式 `fmt.Fprintf(cmd.ErrOrStderr(), ...)` 与 cobra 的错误打印，本次只恢复这条通路。
- 不改 `Logger` 的公开方法集或配置项。

## Decisions

### 1. 规则是"只关自己打开的 sink"，不是"跳过 os.Stderr"

实现上直接删掉 `ReplaceDefault` 与 `Close()` 里对任意 `io.Closer` 的关闭分支，只保留对 `lj` / `errLj` 的关闭。替代方案是加一个 `if c == os.Stderr { skip }` 之类的例外——那只是把同一个错误缩小了一格：测试缓冲、`io.Pipe`、任何未来的共享 writer 仍会被误关，而"日志器不拥有别人的 writer"这条规则本来就有唯一判据（是否由 `New` 从路径打开）。规则清楚，就不需要例外表。

### 2. 判定依据用现有字段，不新增"所有权"标记

`lj` / `errLj` 非 nil 恰好等价于"这个 sink 是本日志器从路径打开的"：`New` 只在落文件时设置它们，回退到 `os.Stderr` 时两个都保持 nil。因此关闭逻辑天然只需要这两个字段，不需要新状态，也不会与既有语义漂移。

### 3. 标准错误的可用性用子进程探针验证

这个缺陷的破坏是进程级的：一旦关掉 fd 2，测试二进制自己的日志与后续用例的诊断也一起消失，在进程内断言会污染整个测试运行。因此用"测试二进制以 `-test.run` 自我调用 + 环境变量标记"的子进程探针：子进程默认日志器 → `ReplaceDefault`(文件日志器) → 向 `os.Stderr` 写一行 → 以退出码与标准输出报告结论。父进程只读子进程的结论，不受影响。

### 4. "自己的 sink 仍被释放"用重命名探针，而不是 fd 计数

lumberjack 不暴露"已关闭"状态，fd 列表在 macOS 上是 fdescfs（`/dev/fd/N` 不是指向目标文件的符号链接），按路径计数会得到假阴性。改用行为探针：先写一行让 sink 打开文件，把文件改名走，`ReplaceDefault` 之后**直接**向捕获到的旧 sink 写一行（经日志器写会落到新 sink 上，这一点第一次实现时就踩到了）——若 sink 已被释放，lumberjack 会重开并重建原路径；若没释放，写入会进到改名后的 inode。两个观察点（原路径是否重建、改名后文件是否收到该行）方向相反，判定不含歧义。

### 5. 保留"安装时清空采样与事件环"的既有行为

`ReplaceDefault` 仍重置 `samples` 与 `events`：新配置的级别与 sink 下，旧采样窗口没有意义。本次改动只动关闭逻辑，不扩大范围。

## Risks / Trade-offs

- **替换时若旧日志器的 writer 既不是 lumberjack 也不是我们创建的，句柄可能不再被释放**——这是有意的取舍：日志器无法安全地释放不是它打开的东西，能泄漏的只有"调用方自己塞进来的 writer"，而生产路径不存在这种调用（`New` 只产生上述两种 writer）。
- **子进程探针增加一次测试二进制启动开销**（约几十毫秒），换来的是唯一能真实复现该缺陷的观察方式。
- 残留影响：修复后新启动的进程恢复终端输出；用户当前正在运行的挂载进程仍持有已关闭的 fd 2，需要重启挂载才能看到终端输出（不影响数据与日志文件）。
