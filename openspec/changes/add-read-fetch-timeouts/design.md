## Context

真实测试证据（2026-11-04，115 挂载）：

- `probe test read --size 64m --samples 2 --cache-mode both --pattern both` 在 prepare 完成后进入冷读，读取到约 17.5 MiB 后停住。
- 挂载进程 goroutine dump 显示：FUSE `Read` → `readChunkRangeWithRuntime` → `waitWindow` 在 `select` 中等待；对应窗口的预取 goroutine 停在 `readWindowRange` → `ReadAllLimited` → `http.body.Read`，已经 1 分钟没有新字节。
- 挂载日志没有错误，只有周期性的 `Getattr "/"`；后续 `ls`、`debug raw`、`umount -f` 全部阻塞，进程进入 `?E` 状态，只能强杀。
- 探针进程同样没有超时，测试本身无法失败退出。

结论：provider 连接停住时，读层没有失败边界，等待者和预取 goroutine 都不会自行结束。

## Goals

- 一个停住的 provider 连接必须在有限时间内让窗口取数失败，并释放调度资源。
- 前台读返回明确错误；后台预取静默取消，不污染调用方。
- 慢但仍在前进的 provider 不能被误杀。
- 不新增用户配置，默认值可按驱动调整。
- 超时行为可观测、可测试，并能用真实云盘回归。

## Non-Goals

- 不改上传路径的超时。
- 不实现跨请求的通用重试框架。
- 不改变成功读的缓存准入、并行策略或 `drive.Driver.Read` 契约。

## Decisions

### 1. 超时放在读层，而不是只靠 HTTP client

只设置 `http.Client.Timeout` 会覆盖整个请求，无法区分“慢但在前进”和“完全停住”，也覆盖不到驱动内部的多次 Range、加密包装层和本地文件源。读层需要按窗口统一约束。

决定：

- 读层为每次窗口取数派生带 deadline 的 context。
- 驱动 HTTP client 增加响应头超时，避免连接建立/首包阶段无限等待。
- body 读取增加空闲超时：连续 N 秒没有新字节即中止；这是主判据。
- 单次 fetch 总上限作为兜底，防止持续滴流但永不完成。

备选：只在每个驱动里加超时（拒绝，重复实现且无法覆盖 VFS 等待者）；只在 FUSE 回调加 deadline（拒绝，预取和直读路径仍然无界）。

### 2. 前台与预取共享超时模型，失败语义不同

- 前台窗口：超时返回 `ErrorCategoryTimeout`，等待者收到错误，FUSE 映射为 EIO。
- 后台预取：超时视为取消原因 `timeout`，只记录事件并释放预取许可，不向调用方传播。
- `ReadStream`：前台窗口语义，错误返回给流读取方。

### 3. 超时值由驱动读配置派生

在 `drive.ReadProfile` 增加：

```go
type ReadProfile struct {
    // 现有字段...
    FetchIdleTimeout  time.Duration // 连续无字节上限
    FetchTotalTimeout time.Duration // 单次窗口取数上限
}
```

默认值取保守值（例如空闲 30s、总上限 5min），慢速驱动可覆盖。不新增用户配置；后续如果需要，再按驱动参数暴露。

### 4. 一次幂等重试

Range GET 是幂等请求。窗口取数超时后允许重试一次；重试仍超时则整窗失败。已经开始向调用方返回字节的流不重试。

### 5. 等待者与加载者共享失败

窗口加载状态需要携带错误：加载失败或超时后，等待同一窗口的读立即返回同一错误，而不是重新发起加载或继续等待。与现有 `windowLoad.done` 合并语义一致，只增加错误字段和超时路径。

### 6. 资源释放

超时路径必须：

- 取消 body 读取并关闭连接。
- 释放全局读槽位和单文件预算。
- 释放预取许可。
- 从 `windowLoad` 注册表移除失败窗口。
- 记录取消原因 `timeout`。

### 7. 可观测性

- 读事件增加 `cancel_reason=timeout`、`wait_us`、`fetch_us`。
- 调试快照的 runtime 增加超时计数和最近一次超时窗口信息。
- 探针在超时后返回结构化失败（挂载、文件、offset、已等待时间），不再无限等待。

## Migration Plan

1. 先加模型与默认值，不接线（纯新增字段，行为不变）。
2. 接前台窗口取数：超时、错误传播、资源释放；用 fake 驱动的停住 body 场景验证。
3. 接预取：超时静默取消；验证预取 goroutine 不泄漏。
4. 接 `ReadStream` 与直读路径，保持语义一致。
5. 驱动 HTTP client 增加响应头超时和 body 空闲超时，慢速驱动覆盖默认值。
6. 增加诊断字段与探针超时。
7. 真实云盘回归：115 冷读不再无限挂起；quark-test / 123 读性能不回归。

## Risks

- **误杀慢速 provider**：空闲超时设置过短会中断正常但慢的下载。用“连续无字节”而不是平均速率，并允许驱动覆盖；默认值取保守值。
- **重试放大流量**：只允许一次，且仅在前台窗口尚未返回字节时重试。
- **FUSE 错误语义变化**：超时从“挂起”变为 EIO，调用方会看到失败而不是卡住；这是期望行为，但需要在文档和探针中说明。
- **加密/包装层**：超时 context 必须贯穿 crypt 包装层到原始驱动，避免包装层捕获错误后继续等待。
- **并发窗口**：同一文件多个窗口同时超时时要避免重复释放槽位；资源释放必须幂等。

## Validation

- fake 驱动 body 停住：前台读在配置超时内返回 timeout，槽位和预取许可归零，无 goroutine 泄漏（goleak）。
- 慢速但持续前进的 body：不触发空闲超时，读成功。
- 预取超时：调用方读不受影响，预取计数归零，诊断记录 `timeout`。
- 窗口等待者：加载者超时后等待者立即收到错误。
- 真实 115：冷读在超时后失败退出，挂载仍可响应 `ls` 和卸载。
- 真实 quark-test / 123：正常读的吞吐与缓存命中不回归。
