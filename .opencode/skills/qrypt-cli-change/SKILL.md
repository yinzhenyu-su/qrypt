# Qrypt CLI Change

## Where the code lives

- Commands are grouped by domain under `internal/cli/<domain>/`.
- Each group exposes `NewCommand(rt Runtime)` and registers subcommands there.
- The root tree is assembled in `internal/cli/command_root.go`; add the new
  group there only when creating a new top-level domain.
- Runtime access goes through the narrow `Runtime` interface in the package,
  backed by `internal/cli/runtime`. Do not reach into global state.
- Use the shared helpers in `internal/cli/runtime`: `NoArgs`,
  `ExactNamedArgs`, `CommandGroupArgs`, `FlagStringValue`, config/state
  resolution, JSON writers, and the filesystem builder. Match the closest
  existing command instead of inventing a new pattern.

## Implementation steps

1. Add the command with `Use`, `Short`, `Long`, `Example`, `Args`, `RunE`.
   Prefer the surrounding style: short one-line `Short`, multi-line `Long`,
   real examples that work after installation (`qrypt ...`, not `./qrypt`).
2. Define flags on the command or its persistent parent. Mark required flags
   and validate mutually exclusive combinations early; usage errors should not
   print a stack of unrelated help.
3. Return actionable errors; use `cliruntime` error helpers where the package
   already does. Machine output (`--json`) must stay stable; human output
   (`--verbose`) may be richer.
4. Register the command in its group, and the group in
   `internal/cli/command_root.go` if new.
5. Add a CLI test under `internal/cli/` using `NewRootCommand()`:
   ```go
   root := NewRootCommand()
   root.SetOut(&out)
   root.SetErr(&errOut)
   root.SetArgs([]string{"fs", "journal", "--cache-dir", dir, "prune", "--failed", "--json"})
   err := root.Execute()
   ```
   Cover success, a usage error, and JSON shape when applicable.

## i18n catalog (required for help text)

The catalog is built from `schema/i18n/cli.en.json` and
`schema/i18n/cli.zh-CN.json`, then generated into
`internal/cli/i18n/catalog_gen.go`.

Add every user-visible key to **both** files:

| Kind | Key |
|---|---|
| command short | `cmd.<command.path>.short` |
| command long | `cmd.<command.path>.long` |
| command examples | `cmd.<command.path>.example` |
| flag usage | `flag.<command.path>.<flag>.usage` |
| output/error | `out.<command.path>...` / `err...` as used by the package |

Rules enforced by `scripts/schema/check-cli-i18n.py`:

- every key exists in both en and zh-CN;
- zh-CN values are translated (not identical to English);
- `*.example` values are identical in both languages;
- format verbs (`%s`, `%d`, ...) match between languages.

Then regenerate and check:

```bash
python3 scripts/schema/gen-cli-i18n.py
python3 scripts/schema/check-cli-i18n.py
```

Do not hand-edit `internal/cli/i18n/catalog_gen.go`.

## Documentation

- Update `docs/for-user/cli.md` for the command syntax and one-line behavior.
- Put the full semantics in a feature guide or `docs/for-user/troubleshooting.md`;
  do not overload `cli.md`.
- `docs/for-user/full-config.md` and `docs/for-user/support-drivers.md` are
  generated by `scripts/schema/gen-config-docs.py` and
  `scripts/schema/gen-driver-docs.py`; update the generator/source, not the
  generated file.
- If the command changes a recovery or safety procedure, update the relevant
  skill (`vfs-upload-recovery`, `qrypt-tests`) as well.

## Gotchas

- `--json` and `--verbose` are often mutually exclusive; reject the combination
  instead of silently picking one.
- `--json` arrays should be `[]`, not `null`, when empty.
- Do not print secrets, cookies, signed URLs, or full configs.
- New flags on a persistent parent affect every subcommand; check help output
  and the command tests.
- Exit codes are part of the contract; use `internal/cli/exit_code.go` helpers
  when a new failure class needs a distinct code.
- Help scaffolding is localized at runtime; English output keeps Cobra wording.
  Do not hard-code translated section labels.

## Verification

```bash
go test ./internal/cli ./internal/cli/... -count=1
python3 scripts/schema/check-cli-i18n.py
scripts/ci/check-all.sh
```

`check-all.sh` also verifies the generated catalog, schema metadata, and
generated docs are in sync. A CLI-only change is not done until that passes.
